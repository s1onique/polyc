## 2. External technical contract

For AArch64 Mach-O, LLVM defines distinct relocation classes:

```text
ARM64_RELOC_PAGE21 / ARM64_RELOC_PAGEOFF12          (ordinary page-relative)
ARM64_RELOC_GOT_LOAD_PAGE21 / ARM64_RELOC_GOT_LOAD_PAGEOFF12  (GOT slot)
ARM64_RELOC_BRANCH26                                (direct branch)
```

The GOT forms explicitly target a GOT slot rather than the final symbol page.

LLVM's Darwin assembler accepts `@PAGE / @PAGEOFF` (ordinary) and `@GOTPAGE / @GOTPAGEOFF` (GOT-loaded).

Therefore this ACT must reason from actual relocation records, not just disassembly strings.

The implementation may choose, based on F2 evidence:

```text
A. GOT-based address materialization
B. direct branch/stub via BRANCH26
C. another Mach-O-native dynamic-reference mechanism
```

provided the produced object is mechanically valid and preserves existing local-symbol behavior.

## 8. Permitted AArch64/Mach-O strategies

### Strategy A - GOT materialization

```asm
adrp xN, _ExtFn@GOTPAGE
ldr  xN, [xN, _ExtFn@GOTPAGEOFF]
blr  xN
```

### Strategy B - direct call/stub via BRANCH26

```asm
bl _ExtFn
```

### Selection rule

Do not freeze A or B before C1/F2 evidence.

The implementation must choose the strategy that matches the semantic operation actually emitted by PolyC.
