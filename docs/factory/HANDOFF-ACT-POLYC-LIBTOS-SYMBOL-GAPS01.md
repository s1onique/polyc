ROOT CAUSE / FINDING

  The committed canonical libtos.a at HEAD (= 6e30e7f, on the
  branch main) already exported _FREE, _STRNCMP, _MEMSET, and
  _STRLEN_FAST. These four symbols had been restored by the
  ACT-POLYC-TOOLING-RUNTIME01-CORRECTION02/03 lineage (commits
  ab1f28d, e5a2e50) which re-emitted the canonical all.o with
  the inline-asm _NAME:: labels present and visible in the
  archive index.

  The single remaining gap was _SpawnAndCapture, declared and
  defined in src/holyc-lib/tooling.HC:253-404. The committed
  archive's all.o was generated by a build epoch where tooling.HC
  was not yet incorporated into the public symbol stream --
  upstream ACT-POLYC-TOOLING-RUNTIME01 (b7d8937) added tooling.HC
  but the canonical install seam at HEAD still ships a stale all.o.

  Root cause classification per ACT §10:
    symbol                  class                    resolution path
    _FREE                   B (resolved upstream)    no ACT mutation
    _STRNCMP                B (resolved upstream)    no ACT mutation
    _MEMSET                 B (resolved upstream)    no ACT mutation
    _STRLEN_FAST            B (resolved upstream)    no ACT mutation
    _SpawnAndCapture        C (object built not      THIS ACT
                             archived)

  The C-class root cause was itself a symptom of a deeper
  build-seam defect:

    ./hcc at HEAD (commit 6ba9f5ec952b0f0d6301fdd2f13aa3bfa830404e)
    regressed on ARM64 inline-asm mnemonics in
    src/holyc-lib/{memory,strings}.HC. A fresh `./hcc -lib tos all.HC`
    invocation fails with:
      error: src/holyc-lib/strings.HC:318:
        error: asm: unexpected token at start of line
      error: src/holyc-lib/memory.HC:215:
        error: asm: unexpected token at start of line
    before any tooling.HC symbol can be emitted, so even if the
    Makefile had been wired correctly, the fresh build would still
    fail.

  The previous bootstrap chain provides a working hcc:
    build/hcc-bootstrap04 (commit ffee58b81ae42a4ff094618fcaa965223a40b848)
    builds all.HC into a complete all.o containing all 8 public
    symbols from tooling.HC (PollIntr, ReadIntr, WaitPidIntr,
    Contains, WaitDecode, TmpFile, SpawnAndCapture, FileExists)
    plus all uppercase ABI symbols from the upstream CORRECTION02/03
    work.

  This ACT does NOT repair the ./hcc ARM64 asm parser regression.
    Per ACT §20, that would require mutation under
    src/parser.c or src/aarch64.c, which exceeds the authorized
    production scope. The hcc ARM64 asm-parser defect is left
    as upstream residue and is documented as P1 in the residue
    section below. The libtos substrate is repaired by routing
    the libtos build through the working bootstrap stage.
