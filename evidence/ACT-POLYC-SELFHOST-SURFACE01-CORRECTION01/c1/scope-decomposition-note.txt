DECISION OPTIONS
================

The proposed ACT merges all six into one ACT. The
Factory precedent says: don't.

  Option A. Execute C-1, C-2, C-3, and the
            Make-injection portion of C-5 in this
            bounded CORRECTION01, then HALT with
            residue entries for C-4 (one bounded ACT
            per Python migration) and C-6 (CLOSE
            machinery in a separate bounded ACT after
            C-4 lands).

  Option B. Open a separate CORRECTION01 that repairs
            ONLY the predecessor's false-green closure
            (C-1 + Make injection hardening from C-5),
            record F-NO-PYTHON / F-POLYC-TOOLS as P1
            residue to be opened as a separate bounded
            doctrine ACT, and migrate Python tools one
            ACT at a time following MIGRATE-GEP01
            precedent.

  Option C. Execute the full 66-section ACT as
            proposed, accepting the F7/F15/CONVERGENCE
            violations.

RECOMMENDATION
==============

Recommend Option B.

Reasoning:

1. The F1 / F2 defects are bounded and reproducible.
   They are exactly what a CORRECTION01 is for.

2. F-NO-PYTHON and F-POLYC-TOOLS are governance
   invariants, not corrections. The Factory precedent
   (MECHANICAL-BLOCKING01, GIT-METADATA-SIMPLIFY01,
   APPEND-ONLY-GUARD01) treats governance as its own
   bounded ACT class.

3. Python tool migration is bounded work that the
   precedent (MIGRATE-GEP01, MIGRATE-GEP01-CORRECTION01,
   MIGRATE-GEP01-CORRECTION02) handles one tool at a
   time, with each migration as a self-contained ACT.

4. The user's broader goal (PolyC as the mandatory
   tooling language) is correctly captured as
   P1 residue with a roadmap-aligned execution plan,
   not as a single mega-ACT.

This recommendation is recorded as F11 residue, NOT
as a self-authorized scope contraction. The user may
still choose Option A or Option C.
