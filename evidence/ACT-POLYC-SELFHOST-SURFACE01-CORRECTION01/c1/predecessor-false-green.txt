Finding F2: Make recipe injection via COMPONENT / STAGE.
----------------------------------------------------

The Makefile lines 977 and 982 in the predecessor ACT
read:

  selfhost-component-build:
        @test -n "$(COMPONENT)" || ...
        @test -n "$(STAGE)"    || ...
        ./tools/selfhost/selfhost-component.sh \
            build COMPONENT=$(COMPONENT) STAGE=$(STAGE)

GNU Make expands variable references in recipes before
sending the command to the shell. With:

  COMPONENT='foo;touch /tmp/sentinel_C'
  STAGE='0;touch /tmp/sentinel_S'

a sentry run produced:

  $ ls -la /tmp/sentinel_*
  -rw-r--r--  ...  /tmp/sentinel_C
  -rw-r--r--  ...  /tmp/sentinel_S

Sentinels were created. Both COMPONENT and STAGE
injection vectors execute arbitrary commands. The
shell script's own arg-validation runs AFTER the
injected `;touch` already executed.

(B1 + B3: a mechanically demonstrated safety
invariant is violated. A bug-bounty or CI injection
can hijack the build host.)

The selfhost-registry-validate recipe (line 985)
also invokes python3 unconditionally, which is a
parallel Python-runtime dependency defect.
