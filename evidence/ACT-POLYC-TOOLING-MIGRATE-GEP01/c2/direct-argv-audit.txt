============================================================
4. Architectural justification
============================================================

The PolyC harness uses only the following substrate:

  SpawnAndCapture(...)  -> execv() of the resolved argv
  FileRead(path)        -> reads file into a buffer
  FileWrite(path, ...)  -> writes buffer to file
  FileExists(path)      -> stat() presence check
  Contains(haystack, needle)
                         -> libc strstr wrapper
  VerdictPass / VerdictFail
                         -> aggregate verdict object
  StrPrint(NULL, fmt, ...)
                         -> format into a fresh buffer
  Free / BytewiseFree   -> release buffers
  FileRead(path, &sz)   -> file slurp

The bare tool names (llvm-as, opt, python3) are resolved
by a HARNESS-LOCAL helper ResolveTool() that walks
getenv("PATH") and FileExists() each candidate. This is
necessary because SpawnAndCapture uses execv() which does
NOT perform PATH lookup (POSIX contract).

The local ResolveTool helper does NOT widen
src/holyc-lib/tooling.HC. It is purely harness-local.
