## Pre-existing failure analysis

`64_sret_x8.HC` was already failing under the entry `./hcc` (the
stage0 baseline). It uses `../../hcc` as a relative path from the
test's `cd src/tests/` working directory, but when invoked from /tmp
the relative path resolves differently. This is a test-harness
limitation not caused by the parser-padding migration.

```sh
$ ./hcc --install-dir=$(pwd)/build/test-prefix src/tests/64_sret_x8.HC -o /tmp/t64
sh: ../../hcc: No such file or directory
Test - indirect struct return C interop: FAILED: 1/3
```

The failure is identical between `./hcc` (legacy C) and `build/hcc`
(PolyC delegation). It is therefore NOT a `PARSER_NEW_FAILURE`
attributable to this ACT.

```text
PARSER_NEW_FAILURES=0
```

## Halt semantics

A genuine new parser failure (one that passes under `./hcc` but fails
under `build/hcc`) would trigger `HALT_PARSER_REGRESSION`.
