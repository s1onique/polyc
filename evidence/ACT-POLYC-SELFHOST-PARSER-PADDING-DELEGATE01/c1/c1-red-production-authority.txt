## Evidence

### Production source does not reference BootstrapCalcPadding

```sh
$ grep -rn 'BootstrapCalcPadding' src/
(no output)
```

### Production binary does not contain the symbol

```sh
$ nm ./hcc | grep BootstrapCalcPadding
$ echo $?
1

$ nm build/hcc | grep BootstrapCalcPadding
$ echo $?
1
```

(Exit code 1 means grep found no matches.)

### Production binary DOES contain legacy CalcPadding

```sh
$ nm -gU build/hcc | grep -E '_CalcPadding|_ParserLegacyCalcPaddingOracle'
000000010003abac T _CalcClassSize
000000010003ac18 T _CalcPadding
000000010003ab68 T _CalcUnionSize
000000010003ac3c T _ParserLegacyCalcPaddingOracle
```

### Subject object contains the symbol but is not linked into production

```sh
$ nm build/parser-padding-subject.o | grep BootstrapCalcPadding
0000000000000000 T _BootstrapCalcPadding
```

### PolyC subject object SHA

```sh
$ sha256sum build/parser-padding-subject.o
187a4de9465e8dbe3c640484b05540daaad4a3267dd1543a169e3c304b02d5b1  build/parser-padding-subject.o
```

## Conclusion

The PolyC implementation is qualified and reachable as a component
object, but it is not linked into the production `./hcc` binary, and
no production source file references it. Production authority for
`CalcPadding` semantics is held exclusively by
`src/parser.c::CalcPadding` (legacy C).

This is the expected RED state. Migration to PolyC authority is the
work of C2.
