## Build check

```sh
$ nm /tmp/parser-padding-subject.mutated.o | grep BootstrapCalcPadding
0000000000000000 T _BootstrapCalcPadding
```

The symbol survives the single-byte 0x90 write at offset 100. The
mutated object still has the `_BootstrapCalcPadding` symbol exported
and remains link-compatible.

```text
MUTATED_SUBJECT_BUILD=PASS
```

## Production impact

The production `./hcc` binary does NOT reference the subject object at
all. Mutating the subject object therefore has ZERO observable impact
on production parser/layout output.

```sh
$ nm ./hcc | grep BootstrapCalcPadding; echo "exit=$?"
1
$ nm build/hcc | grep BootstrapCalcPadding; echo "exit=$?"
1
```

(Both binaries contain zero references to `BootstrapCalcPadding`.)

```text
MUTATED_SUBJECT_PRODUCTION_DIVERGENCE=NO
```

## Conclusion

The PolyC subject is not load-bearing in the production compiler.
Mutating it has no observable effect on production parser output.

This is the expected RED state for pre-migration. After C2, the same
mutation MUST produce observable divergence (ACT §24 N01 contract).
