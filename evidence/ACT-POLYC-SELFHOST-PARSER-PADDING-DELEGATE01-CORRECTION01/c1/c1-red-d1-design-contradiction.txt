## Why the generic seam was unusable (engineering rationale, verified)

`src/CMakeLists.txt` binds the generic flag to the lexer stage binaries:

```sh
$ grep -n 'HCC_USE_SELFHOST_COMPONENTS' src/CMakeLists.txt
185:# `HCC_USE_SELFHOST_COMPONENTS` flag (which would also require linking
279:    # is HCC_USE_SELFHOST_COMPONENTS. The legacy macro
283:        HCC_USE_SELFHOST_COMPONENTS
292:    # object is now a HARD prerequisite: HCC_USE_SELFHOST_COMPONENTS
311:    # HCC_USE_SELFHOST_COMPONENTS is enabled.
429:        HCC_USE_SELFHOST_COMPONENTS
567:        HCC_USE_SELFHOST_COMPONENTS
```

Those sites are the `hcc-bootstrap02` / `hcc-bootstrap03` / `hcc-bootstrap04`
lexer-stage targets. Adopting the generic flag for the production `hcc`
target would have required linking all five lexer PolyC subject objects
(`BootstrapScanIdent`, `BootstrapClassifyOperator`,
`BootstrapScanScalarLiteral`, `BootstrapScanTrivia`,
`BootstrapLinkDirective`) -- five artifacts that are outside the
parser-padding slice's authorized scope. The dedicated flag isolates the
parser-padding migration so it can land independently.

This is a deliberate architectural choice, not a temporary workaround.

## Prospective authorization (JOB 1)

```text
CORRECTION01_AUTHORIZED_DESIGN=HCC_USE_SELFHOST_PARSER_PADDING
DEDICATED_MACRO_REQUIRED=YES
DEFAULT_PRODUCTION_VALUE=ON
LEGACY_STAGE0_PATH=EXPLICIT
PRODUCTION_SOURCE_CHANGE_REQUIRED=NO
```

### Why `PRODUCTION_SOURCE_CHANGE_REQUIRED=NO`

The dedicated seam is ALREADY implemented and ALREADY production-active.
`src/CMakeLists.txt` declares `option(HCC_USE_SELFHOST_PARSER_PADDING ... ON)`
-- default ON -- and `src/parser.c::CalcPadding` already delegates to
`BootstrapCalcPadding` under that macro. CORRECTION01 therefore performs
NO production source mutation: it prospectively authorizes the existing
implementation and re-freezes AC13 under the authorized design.

### Legacy stage0 path stays EXPLICIT

The legacy C algorithm survives only inside the `#else` branch of
`src/parser.c::CalcPadding`, reachable solely from the stage0 evidence
path (`build/parser-padding-legacy.o`, compiled WITHOUT the macro). It is
never compiled into the production binary. `LEGACY_STAGE0_PATH=EXPLICIT`.
