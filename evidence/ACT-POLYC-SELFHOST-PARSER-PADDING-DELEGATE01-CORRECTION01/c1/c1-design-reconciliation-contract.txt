## Why the dedicated seam is architecturally correct

1. **Scope isolation.** `HCC_USE_SELFHOST_COMPONENTS` is bound in
   `src/CMakeLists.txt` to the `hcc-bootstrap02` / `hcc-bootstrap03` /
   `hcc-bootstrap04` lexer-stage targets (lines 283, 429, 567). Using it
   for the production `hcc` target would require linking five lexer
   PolyC subject objects that are outside the parser-padding slice.

2. **Independent migrability.** The parser-padding delegation must be
   able to land, be qualified, and be reverted independently of the
   lexer self-host migrations. A dedicated flag gives that property; the
   generic flag does not.

3. **No speculative abstraction.** The dedicated flag adds exactly one
   option and one `target_compile_definitions` call. No bridge header,
   no registry, no framework. This satisfies F8.

4. **Explicit stage0 path.** The legacy C algorithm remains reachable
   only through the `#else` branch, compiled without the macro, in the
   stage0 evidence path (`build/parser-padding-legacy.o`). Production
   never compiles it. This preserves the differential's oracle.

```text

- the generic HCC_USE_SELFHOST_COMPONENTS seam for the parser
- renaming the macro
- adding a bridge header or a component registry
- extending the delegation to any other parser function
```
