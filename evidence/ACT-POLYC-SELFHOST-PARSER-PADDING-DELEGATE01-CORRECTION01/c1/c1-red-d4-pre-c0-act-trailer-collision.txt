
### Why it is structurally unfixable from a forward commit

The three pre-C0 commits are ancestors of HEAD. Their commit messages are
content-addressed Git objects. A forward commit cannot change an
ancestor's message. The available mechanisms are all forbidden here:

```text
git commit --amend     -> replaces an ancestor; forbidden (append-only
                          invariant, enforced by .githooks/pre-push
                          since baf5dbd7)
git rebase              -> forbidden
git reset + recommit    -> forbidden
git replace             -> forbidden (the pre-push hook rejects any
                          non-empty `git replace -l`)
git filter-branch/repo  -> forbidden
```

There is NO validator escape hatch: the FIRST walk terminates only when a
parent does NOT carry `ACT: <id>`. The three pre-C0 commits all carry
it, so the walk always reaches `8393d4d`.
