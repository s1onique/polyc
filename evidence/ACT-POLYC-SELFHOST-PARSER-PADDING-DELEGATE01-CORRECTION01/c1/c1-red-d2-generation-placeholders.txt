## Why descriptive metadata is not proof

The CORRECTION01 ACT (section 11) requires, for every generation, a
complete set of real identities. The predecessor's rows lack ALL of the
following for G2/G3:

```text
compiler_sha256                        -> placeholder prose
exact_subject_build_command            -> absent
subject_build_command_sha256           -> absent
production_binary_path (distinct)      -> absent (shared with G1)
production_binary_sha256               -> placeholder prose
exact_production_build_command         -> absent
production_build_command_sha256        -> absent
exact_fixture_command                  -> absent
fixture_command_sha256                 -> absent
fixture_output_path                    -> absent
fixture_output_sha256 (real capture)   -> absent
execution_rc                           -> absent
```

The predecessor's descriptive notes ("independently built", "distinct
because ...") are prose assertions. Per F13 (evidence over persuasive
prose) and the ACT's explicit rejection of placeholders, they are NOT
accepted as proof.

## What CORRECTION01 must do (JOB 2)

Actually execute, in the C2 phase, for G2 and G3:

1. Build the PolyC subject object with the generation's own compiler
   (`./build/hcc-bootstrap02` for G2, `./build/hcc-bootstrap03` for G3),
   recording the real command and the real object SHA-256.
2. Link an INDEPENDENT production `hcc` binary for that generation,

3. Execute the frozen fixture set with THAT production binary, capturing

4. Record every one of the required provenance fields as a real value.

No placeholders. No copied outputs. No inferred SHAs. If a required
field cannot be produced with a real value, the halt is
