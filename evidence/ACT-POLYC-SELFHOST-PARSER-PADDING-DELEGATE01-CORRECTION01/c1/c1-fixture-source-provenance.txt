## Resolution: deterministic REGENERATION from committed sources

Per ACT section 14, C1 MUST identify the real source or the regeneration
procedure. The regeneration procedure is used here. The regenerated
fixtures are COMMITTED under this ACT's evidence tree so that every
generation in C2 uses a byte-identical, immutable, version-controlled
fixture source:

```text
evidence/ACT-POLYC-SELFHOST-PARSER-PADDING-DELEGATE01-CORRECTION01/fixtures/fixture_alignof.HC
evidence/ACT-POLYC-SELFHOST-PARSER-PADDING-DELEGATE01-CORRECTION01/fixtures/fixture_u0_tail.HC
evidence/ACT-POLYC-SELFHOST-PARSER-PADDING-DELEGATE01-CORRECTION01/fixtures/fixture_inheritance.HC
```

### Honest disclosure about the historical output SHA

The predecessor's recorded FIXTURE_ALIGNOF output SHA-256 was
`8c9437a04195cdcbaa2dd38f0b31c59bede2de0bd7025217560c8ae2de18d83c`.
The regenerated fixture's output SHA-256 is
`86c75cd71eacaf9121d5de93b88921ec3c129a766b8e72955c33add329fff190`.

These DIFFER. The difference is NOT a semantic divergence: every value
the predecessor pinned is reproduced exactly (table above). The
difference is in the byte-level FRAMING of the output file -- the exact
header line and any trailing summary lines that the ephemeral
`/tmp/fixture_alignof.HC` emitted are not recoverable from the committed
record, because the file itself was never committed.

This was investigated rather than assumed. A systematic search over
plausible header/footer/suffix framings (7200 candidate byte streams
covering 12 line formats x 12 header forms x 25 suffix forms x trailing
newline variants) was executed against the historical SHA and found NO
match. The framing is therefore treated as unrecoverable historical
detail.

Consequences, stated plainly:

1. The CORRECTION01 six-way semantic comparison is performed over the
   REGENERATED fixture set, whose source is committed, immutable, and
   shared byte-identically by all four generations. That comparison is
   therefore fully reproducible and auditable by any future reader.

2. The predecessor's historical output SHA is NOT claimed to be
   reproduced. It is not a CORRECTION01 acceptance predicate (AC11/AC12
   concern the G2/G3 output SHAs, which are frozen from REAL captures in
   C2). The historical SHA is recorded here as historical context.

3. Because the regenerated fixture reproduces every pinned value, the
   migration-semantics conclusion (MIGRATION_DELTA=0) is unaffected.

This is recorded rather than hidden. See the C4 residue for the
recommendation that future production fixtures be committed rather than
written to `/tmp`.
