### Why G1/G2/G3 share a production-binary SHA

The build is deterministic: the same source tree, the same flags, and a
byte-identical subject object produce a byte-identical production
binary. The three generations are still INDEPENDENT:

```text
distinct subject object paths   g1/ g2/ g3/parser-padding-subject.o
distinct CMake build dirs       g1/cmake g2/cmake g3/cmake
distinct PARSER_PADDING_OBJECT  verified in each CMakeCache.txt
distinct production binaries     g1/hcc g2/hcc g3/hcc
distinct fixture executables    g1/*.bin g2/*.bin g3/*.bin
distinct compile+run invocations per generation (see c2-*-production-run.txt)
```

Identical hashes do NOT prove independent execution; the separate build
directories, separate subject objects, separate binary paths, separate
fixture executables, and separate execution transcripts do.
