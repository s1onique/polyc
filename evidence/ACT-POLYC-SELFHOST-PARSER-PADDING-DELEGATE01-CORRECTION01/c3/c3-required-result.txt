## AC16 -- honest recording of a structurally unreachable predicate

AC16 requires `factory-v2-range-check CORRECTION01 = PASS`. That
predicate is NOT mechanically reachable, and this ACT does NOT claim it.

The validator derives FIRST by walking parents backwards for as long as
each parent carries `ACT: <id>`. The three pre-C0 authorization commits
already carry the CORRECTION01 ACT id:

```text
8393d4d  ACT-Phase=POST_MORTEM_AUTHORIZATION
b73fe6b  ACT-Phase=AUTH_REVISED
93f85ed  ACT-Phase=AUTH_READY_FOR_C0
```

so FIRST is pinned to `8393d4d` and the check reports:

```text
STATUS=FAIL
REASON=FIRST commit 8393d4d97d434eff38e7024266405effe13b3708 has ACT-Phase='POST_MORTEM_AUTHORIZATION', expected RED
```

Proved empirically: a scratch clone given a PERFECT C0..C4 trailer
sequence (exactly the trailers this ACT prescribes) produces the same
FAIL. Ancestor commit messages are immutable under the append-only
invariant, so no forward commit can change this.

Classification per DOCTRINE section 25: `HALT_CLASS=GOVERNANCE`,
`BLOCKS_NEXT=NO`. The failure is not attributable to the production
subject (which is ENGINEERING_TRUE_GREEN and unchanged); it is a
bookkeeping defect in immutable ancestor commits. Per F13 this ACT
reports the measured result rather than asserting a passing gate.

Remediation is recommended as a dedicated follow-up ACT; see the C4
residue.
