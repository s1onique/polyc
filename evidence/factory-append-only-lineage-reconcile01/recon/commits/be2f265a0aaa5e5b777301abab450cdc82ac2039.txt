THE EXECUTION-LINKED PROVENANCE WITNESS
  G1/G2/G3 produce byte-identical objects, so a finished object could
  be substituted for another WITHOUT changing the output bytes, and a
  check comparing only (object SHA, compiler SHA) could not see it.
  So each generation's build also produces a witness bound to an
  ACTUAL EXECUTION: a probe built by that generation's OWN compiler,
  linked against that generation's OWN object, and run.

  The five provenance negative controls corrupt or substitute that
  witness and each is REJECTED with a concrete reason:
    CASE-1 a substituted witness        -> REJECT_STAGE_LABELS
    CASE-2 an omitted execution receipt -> REJECT_OMITTED_EXECUTION_RECEIPT
    CASE-3 a changed compiler SHA       -> REJECT_COMPILER_SHA_MISMATCH
    CASE-4 a substituted object         -> REJECT_OBJECT_SHA_MISMATCH
    CASE-5 swapped stage labels         -> REJECT_EXECUTION_RECEIPT_MISMATCH

  The G0 producer is resolved and hashed FROM THE ACTUAL INVOKED
  COMMAND, and the raw receipt, the manifest and the summary are
  generated from ONE recording, so they are single-valued.
