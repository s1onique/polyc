THE DECISION
============
Given a parsed statement, decide whether it is APPENDED to the
compound block's statement list or SKIPPED because it is a
global-variable declaration.  It reads exactly TWO bounded AstKind
values (stmt->kind and stmt->declvar->kind), both copied out of the
host AST node, and produces ONE bounded boolean.  The C side keeps the
AST graph, the allocation, the diagnostics, the recovery point, the
token stream, the scope tables and the list structures.

WHY NOT SUB-002, THE RANK-1 CANDIDATE
=====================================
SUB-002's live condition tests the SAME FIVE AstKind values as the
already-migrated SUB-001 decision, and AST_DEFAULT is unreachable at
that position: src/parser.c:1669 raises "Duplicate default case", so
the inner parseDefaultStatement never returns.

THIS WAS PROVED BY EXECUTION.  A mutant that ADDS AST_DEFAULT to the
SUB-002 condition was built into the REAL compiler in a disposable
detached worktree and the full 90-file production suite was run with
it:

  PRISTINE  376/376  md5=b6f117eb1386ca80f81bc06226e2a741
  MUTANT    376/376  md5=b6f117eb1386ca80f81bc06226e2a741

The assertion sequences are BYTE-IDENTICAL.  The mutation has ZERO
observable effect, so SUB-002 is DUPLICATED CODE rather than a
distinct decision, and transferring it would create a SECOND PolyC
authority for a decision the first authority already owns.  It was
removed from the feasible subset by that machine-verifiable reason and
the selection was re-run.

SUB-003 WAS THEN PROVEN CAUSALLY LOAD-BEARING.  A mutant that removes
its decision makes the REAL compiler fail to compile a program the
pristine compiler accepts ("ERROR: Mapping exists for 1 -> %l2 i64
local"), and drops the 90-file suite from 376 to 371 assertions with
the MD5 changing to dc2f36f1bd63bca22fc7ea57359a770d.
