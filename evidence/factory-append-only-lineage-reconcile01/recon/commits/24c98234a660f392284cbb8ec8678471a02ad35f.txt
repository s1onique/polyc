ACT-POLYC-SELFHOST-PARSER-SLICE04 C2: the PolyC AST-operator component and the production delegation

Migrate the selected candidate's decision into production-authoritative
PolyC, and prove it against the REAL legacy C function.

THE POLYC COMPONENT
  tools/bootstrap/selfhost-parser-slice04.HC implements ONLY the
  selected mapping, as a pure scalar function:

    I64 BootstrapAstBinOpFromToken(I64 token_value) -> I64

  19 mappings transcribed from the legacy switch, -1 as the failure
  sentinel.  No host AST pointers, no allocation, no global state, no
  callbacks, no recovery dependency.  It is compiled by the STAGE-0
  compiler, so the bootstrap chain stays acyclic.

THE PRODUCTION DELEGATION
  src/ast.c's astBinOpFromToken now delegates to the component under
  the dedicated selector HCC_USE_SELFHOST_PARSER_AST_BINOP, keeping its
  exact C ABI: boolean success and conditional output storage.  The
  adapter owns argument projection, success conversion and output
  storage; PolyC owns the DECISION.

  The production object's DISASSEMBLY is the proof that the C decision
  left the production path: the function is now call / test /
  conditionally store / return, with NO jump table and NO enum
  immediates.  The unselected astUnaryOpFromToken still carries its C
  switch and is byte-identical to the entry version.

THE BUILD FAILS CLOSED
  src/cmake/VerifyAstTokenMapObject.cmake resolves the symbol spelling
  from the TARGET object format, rejects an undefined-only, local-only,
  weak-only, empty or missing object, and requires exactly one strong
  global text definition.  All seven controls were EXECUTED and each
  was rejected.  The verification is a custom target, so no stale stamp
  can bypass the current object check.

THE REAL DIFFERENTIAL
  The oracle is src/ast.c compiled WITHOUT the delegation flag.  Its
  object is BYTE-IDENTICAL to the entry production ast.c object
  (sha 144c9836...), it does NOT reference the PolyC symbol, and the
  driver contains no mapping table.
