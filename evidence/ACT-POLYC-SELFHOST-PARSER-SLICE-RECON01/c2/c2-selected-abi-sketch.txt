NEXT_ABI_SKETCH (frozen input to the successor ACT):

  // tools/bootstrap/selfhost-parser-padding.HC
  //
  // Frozen ABI (must match c2-selected-target.txt input/output schemas).
  //
  //   I64 BootstrapCalcPadding(I64 offset, I64 size);
  //
  // Returns the number of padding bytes (0..size-1) needed to align
  // the next field at `offset` to a `size`-byte boundary.
  //
  // Special cases:
  //   - size == 0  -> return 0   (zero-size fields need no padding;
  //                                guards against `% 0` UB)
  //   - offset % size == 0 -> return 0
  //   - otherwise         -> return size - (offset % size)
  //
  // Inputs are pure scalar integers; no pointers, no host identity.

EQUIVALENCE_PROOF:
  BootstrapCalcPadding is byte-equivalent to the C implementation
  src/parser.c lines 430..438 (the body that the corpus-matrix.tsv
  compares against). Equivalence is observable by running the
  direct-differential oracle on a bounded set of (offset, size) pairs.

LEGACY_ORACLE_OBSERVABLE=YES
  Returned int 0..size-1 is the oracle.

  successor). The PolyC component is exercised by the oracle and the

COMPONENT_OBJECT_FIXEDPOINT_FEASIBLE=YES
  BootstrapCalcPadding takes only two scalars. The component can be
  compiled and linked as a standalone translation unit with a tiny
  HC driver that loops over (offset, size) inputs.

CAUSAL_MUTATION_CLASS_DEFINED=YES
  A mutation that returns `size - offset % size` even when size==0
  must be detected by every input with size==0 (oracle rc != 0).
  A mutation that omits the `if (size == 0) return 0;` guard must
  also be detected (off-by-one on the first call).
