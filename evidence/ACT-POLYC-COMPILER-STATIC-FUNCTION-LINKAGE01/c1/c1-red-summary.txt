C1 RED repros mechanically observed:

RED_01: RED_PRIVATE_FNS_STALE_STATE

  CLASS: HALT_JIT_PRIVATE_STATE_LEAK (per ACT §42 taxonomy)

  REPRO:
    hcc -repl << 'EOF'
static I64 Foo() { return 11; }
public I64 Foo() { return 22; }
"%d\n", Foo();
EOF

  OBSERVED:
    JIT: unresolved symbol '_Foo'

  EXPECTED:
    22
    (public Foo from chunk 2 should be globally published;
     the lookup in chunk 3 should resolve it.)

  ROOT CAUSE:
    src/jit-common.c:private_fns is allocated in hccJitNew (line 538),
    populated in hccJitCompileChunk (lines 599-611), and consulted at
    finalize (line 729) -- but NEVER cleared between chunks.

    Chunk 1 compiles static Foo -> private_fns += "Foo"
    Chunk 2 compiles public Foo -> finalize loop encounters _Foo label;
      if (jit->private_fns && mapHas(jit->private_fns, "Foo")) continue;
      The new public _Foo label is FILTERED OUT.
    Chunk 3 tries to print Foo -> looks up host_symbols -> not found.

  FIX SCOPE: src/jit-common.c (one-line correction: clear private_fns
    alongside chunk_fns at the start of hccJitCompileChunk).

  IN-SCOPE per ACT §17 (jit-common.c is pre-authorized).

  ADDITIONAL OBSERVATION:
    private_fns is also never released on hccJitFree (lines 898-904);
    this is a minor leak but is not a linkage defect. Recorded as
    residue; fix in C2 if scope permits.
