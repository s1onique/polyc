CORRECTED §9.4 ALGORITHM (C3.4)

  Producer-binding seam (built during llCreateBlocks or right
  after, BEFORE the IR_PHI dispatch arm runs):

    // new bounded map: IrValue id -> defining IrInstr *
    // built by walking every IrBlock's instructions once
    def_map : LLDefMap { IrInstr **values; u32 cap; }
    llDefMapInit(&lc->def_map, fn->next_value_id);
    listForEach(fn->blocks) {
        IrBlock *b = (IrBlock *)it->value;
        listForEach(b->instructions) {
            IrInstr *ins = (IrInstr *)it->value;
            if (ins->dst) {
                llDefMapSet(&lc->def_map, irVarId(ins->dst), ins);
            }
        }
    }

  C4 IR_PHI dispatch arm (corrected):

    case IR_PHI:

        /* shape validation (unchanged from C3.3) */
        validate bounded short-circuit shape
        validate exact predecessor set

        /* §9.3.2 + §9.4 Option A: counter once per SHAPE
           admission, at the top, BEFORE PI guards. */
        LL_INC_SHAPE_DEPENDENT(lc);

        phi = LLVMBuildPhi(lc->bld, LLVMInt8TypeInContext(lc->ctx), "phi")

        for each incoming (v, ir_pred):

            /* §9.3.1: lookup-only predicate, NOT get-or-create */
            pred_bb = llbmGet(&lc->blocks, ir_pred->id)
            if pred_bb == NULL:
                HALT_PHI_EDGE_MATERIALIZATION_REQUIRED

            /* ensure pred_bb is actual CFG predecessor */
            assert_in_predecessor_set(pred_bb)

            /* v is the previously-lowered incoming value */

            if LLVMTypeOf(v) == LLVMInt8TypeInContext(lc->ctx):
                use v directly (constant/argument case)

            else if LLVMTypeOf(v) == LLVMInt1TypeInContext(lc->ctx):
                /* §9.4 producer check: MUST be IR_ICMP */
                IrInstr *producer =
                    llDefMapGet(&lc->def_map, irVarId(v))
                if (!producer ||
                    producer->op != IR_ICMP ||
                    producer->dst != v) {
                    HALT_PHI_TYPE_CONTRACT_REQUIRED
                          "i1 PHI incoming must be produced
                           by IR_ICMP; got producer=%s or
                           NULL. This is the §9.4 producer
                           binding contract."
                }

                /* PI-2: predecessor has a terminator */
                pred_term = LLVMGetBasicBlockTerminator(pred_bb)
                if pred_term == NULL:
                    HALT_PHI_EDGE_MATERIALIZATION_REQUIRED

                /* §9.3.3 PI-3 narrow: assert v was defined in
                   pred_bb before pred_term. */
                assert_instruction_in_block_before(
                    producer, pred_bb, pred_term)

                /* §9.2 build-position discipline (unchanged) */
                save = LLVMGetInsertBlock(lc->bld)
                LLVMPositionBuilderBefore(lc->bld, pred_term)
                v = LLVMBuildZExt(lc->bld, v,
                      LLVMInt8TypeInContext(lc->ctx),
                      "phi_icmp_zext")
                LLVMPositionBuilderAtEnd(lc->bld, save)

            else:
                HALT_PHI_TYPE_CONTRACT_REQUIRED

            add (v, pred_bb) to PHI incoming list

        cache PHI dst

PRODUCER IDENTITY PROOF

  Why three predicates (producer != NULL, producer->op == IR_ICMP,
  producer->dst == v)?

  - producer != NULL: catches function-parameter i1s (no
    defining IrInstr) and constants.
  - producer->op == IR_ICMP: catches IR_FCMP, IR_TRUNC of a
    bool parameter, IR_ZEXT/IR_SEXT into i1, etc.
  - producer->dst == v: catches a producer that wrote to a
    DIFFERENT IrValue (id aliasing safety; in practice the
    def_map is keyed by IrValue id so this should always be
    true, but the explicit check defends against map corruption).

  Constants and arguments bypass the producer check because
  they have no defining IrInstr (producer == NULL). They are
  LLVM i8 by construction (no normalization needed) and the
  discriminator naturally falls through to "use directly"
  without ever entering the i1 branch.

  The current C3.3 §9.3.5 algorithm would treat any cached i1
  as needing normalization, regardless of producer. C3.4
  freezes the producer-checked discriminator.

COUNTER VS HALTING SEMANTIC (Q3)

  Option A (frozen): "static shape admitted by dispatch
  contract". Counter increments ONCE at the top of the arm,
  BEFORE PI-1/PI-2/PI-3 guards, IF AND ONLY IF the SHAPE has
  been admitted by the dispatch contract. The PI guards then
  either succeed (lowering completes) or HALT (lowering
  aborts). Either way, the counter has fired exactly once.

  Rationale (per expert): matches the existing capability
  accounting convention (one increment per opcode at the top
  of the arm; per src/llvm-backend.c:2024, 2229, 2514, 2846,
  3029, 3153). Avoids needing transactional counter rollback.

  Note: this is a SEMANTIC sharpening, not a behavior change.
  C3.3 §9.3.2 already said "exactly one increment per
  successfully accepted IR_PHI shape". The "successfully
  accepted" wording is now sharpened to "static shape
  admitted by dispatch contract" -- which is what the
  algorithm actually does.

NEW ACCEPTANCE CRITERIA (AC53-AC56)

  AC53 C3.4 freezes the producer-opcode binding for the i1 ->
       i8 normalization path. The discriminator MUST verify:
         producer != NULL
         producer->op == IR_ICMP
         producer->dst == v
       On any failure: HALT_PHI_TYPE_CONTRACT_REQUIRED.
       Constants and arguments bypass the producer check
       (they have no defining IrInstr) and are handled via
       the i8 "use directly" branch.
  AC54 C3.4 freezes the producer-binding seam as a new bounded
       map `def_map : IrValue id -> defining IrInstr *` built
       during llCreateBlocks (or right after). The map is a
       structural twin of the existing llbmGet block map.
  AC55 C3.4 sharpens the counter semantic from "successfully
       accepted" to "static shape admitted by dispatch
       contract" (Option A). Counter increments ONCE at the
       top, BEFORE PI guards, regardless of subsequent
       halting.
  AC56 C3.4 requires mechanical-witness evidence of:
       (a) producer leak (current vs corrected discriminator),
       (b) producer-checked + counter algorithm over 4 cases,
       (c) no committed witness binaries (P2 hygiene).
