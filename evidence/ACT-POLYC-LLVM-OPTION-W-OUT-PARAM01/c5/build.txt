ACT-POLYC-LLVM-OPTION-W-OUT-PARAM01 C5 BUILD PROCEDURE
-------

Date: 2026-09-12 (corrected from 2026-12-09).

This file describes the exact commands used to reproduce
the C5 evidence end-to-end. All steps assume:

  * Working directory is the repository root.
  * LLVM toolchain (llvm-as, opt, clang) is on PATH.
  * hcc binary is at repository-root/hcc (per closure-truth.txt).
  * The C4 install dir /tmp/polyc-c4 is the carry-over
    from C4 IMPL-B.

VECTORS
-------

C5 exercises the FROZEN C1 binding fixture Tests 05-10
(the subset internally consistent with the frozen
function body). Tests 01-04 are INCONSISTENT_WITH_FROZEN_BODY
and are NOT exercised at runtime. See
frozen-binding-classification.txt for the per-test
classification and reasoning.

The reviewer-prescribed nonzero-cursor probes are T08
(src="abc foo", len=7, cursor=3 -> (3,0)) and T09
(src="abc foo", len=7, cursor=4 -> (7,3)).

SUBJECT COMPILE
-------

$ hcc --emit-llvm --install-dir=/tmp/polyc-c4 \
      -o /tmp/scanident-fixture.ll \
      evidence/ACT-POLYC-LLVM-OPTION-W-OUT-PARAM01/c5/scanident-fixture.HC
hcc exit code: 0

$ llvm-as /tmp/scanident-fixture.ll -o /tmp/scanident-fixture.bc
llvm-as exit code: 0

$ opt --passes=verify /tmp/scanident-fixture.bc -S \
        -o /tmp/scanident-fixture-opt.ll
opt exit code: 0

RUNTIME BINDING (hcc-emitted subject -> native executable)
-------
This is the end-to-end runtime evidence. The hcc-emitted
LLVM IR is compiled to a native aarch64 object, linked
with a driver that declares ScanIdent externally (the
driver does NOT define ScanIdent itself), and the 6
FROZEN C1 binding-fixture Tests 05-10 are run against
the hcc-generated binary. The reviewer-prescribed
nonzero-cursor probes T08 and T09 are included.

$ clang -c /tmp/scanident-fixture.ll -o /tmp/scanident-subject.o
$ cc -Wall -Wextra -c scanident-runtime-driver.c \
        -o /tmp/scanident-runtime-driver.o
$ clang /tmp/scanident-runtime-driver.o /tmp/scanident-subject.o \
          -o /tmp/scanident-runtime
$ /tmp/scanident-runtime

Expected:
* clang -c exit code: 0 (warning: overriding module target triple)
* cc -c exit code: 0
* clang link exit code: 0
* runtime exit code: 0
* "ALL 6 FROZEN BINDING TESTS PASS (hcc-emitted subject)"
  on stdout
* 6 lines of "Test TNN: ... PASS" output, including T08
  and T09 nonzero-cursor probes.

This proves that the hcc-emitted LLVM IR for ScanIdent
computes the FROZEN C1 binding-fixture expected outputs
for every consistent test when executed as a native
binary.

RUNTIME COMPARISON (reference vs hcc-emitted subject)
-------
A stronger arrangement: the C reference (in
scanident-comparison.c, compiled with cc) and the
hcc-emitted subject (linked from scanident-subject.o)
are run side-by-side on each of the 6 frozen vectors.
Both implementations must agree AND match the frozen
expected outputs. T08 and T09 are explicitly marked
_NZCURSOR in the output.

$ cc -Wall -Wextra -c scanident-comparison.c \
        -o /tmp/scanident-comparison.o
$ clang /tmp/scanident-comparison.o /tmp/scanident-subject.o \
          -o /tmp/scanident-comparison
$ /tmp/scanident-comparison

Expected:
* exit code 0
* "ALL 6 FROZEN BINDING TESTS PASS (ref == sub == expected)"
* 6 lines of "Test TNN[_NZCURSOR]: ... sub_ok=Y agree=Y PASS"

This proves that the hcc-emitted LLVM IR is
behaviorally equivalent to the C reference for every
frozen C1 binding-fixture test that is internally
consistent with the frozen function body.

RUNTIME ORACLE (C reference, standalone)
-------
The standalone C reference implementation at
scanident-oracle.c also runs the 6 frozen binding tests
and serves as a single-implementation oracle.

$ cc -Wall -Wextra -o /tmp/scanident-oracle \
      scanident-oracle.c
$ /tmp/scanident-oracle

Expected:
* cc exit code: 0
* scanident-oracle exit code: 0
* "ALL 6 FROZEN BINDING TESTS PASS (C reference)" on stdout
* 6 lines of "Test NN (...): ... PASS" output
