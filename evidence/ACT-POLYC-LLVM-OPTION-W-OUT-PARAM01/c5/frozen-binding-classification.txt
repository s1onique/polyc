C5 FROZEN-BINDING CLASSIFICATION (per reviewer diagnosis)
=========================================================

The frozen C1 binding fixture in
../c1/scanident-binding-fixture.txt defines 10 tests for the
frozen ScanIdent body:

  line 1: I64 start = cursor;
  line 2: while (cursor < len) {
  line 3:   U8 ch = src[cursor];
  line 4:   if (ch == ' ' || ch == '\t' || ch == '\n') break;
  line 5:   cursor = cursor + 1;
  line 6: }
  line 7: *out_cursor = cursor;
  line 8: *out_len = cursor - start;
  line 9: return 0;

The frozen body ONLY stops at whitespace (' ', '\t', '\n').
It does NOT recognize alphabetic/digit/underscore transitions.

The frozen fixture's Tests 01-04 describe "identifier"
behavior (alpha/underscore followed by alphanumeric that ends
at first non-identifier-character), but the body never had
such recognition. Therefore Tests 01-04 are internally
inconsistent with the frozen body.

Tests 05-10 are internally consistent with the frozen body
(whitespace-only stop, optional nonzero initial cursor).

GOVERNANCE RESIDUE
==================

Tests 01-04's frozen inputs and expected outputs are
contradictory with the frozen function body. They describe
identifier-character recognition that does NOT exist in
this body. Per the new doctrine ("don't mutate green
production code to make contradictory historical prose
true"), this is classified as governance/oracle residue:

  - the compiler is correctly emitting a body that stops
    only at whitespace;
  - the frozen prose tests 01-04 are wrong about what the
    body does;
  - fixing this would require a historical ACT (NOT in
    this C5 scope) and either (a) rewriting the frozen
    Tests 01-04 to use inputs that match the body or
    (b) documenting the contradiction and proposing a
    future ACT to decide whether to (a) update oracle
    or (b) extend the body with identifier-character
    recognition (much larger scope).

This residue is non-blocking for C6 CLOSE because:
  1. The frozen Tests 05-10 (which are consistent with
     the frozen body) all PASS on the hcc-emitted
     subject, on the C reference, and agree with the
     frozen expected outputs.
  2. Tests 08 and 09 specifically provide the strongest
     runtime coverage of the Option-W slot machinery
     (nonzero initial cursor).
  3. No production mutation is indicated by this
     residue; the contradiction is in the historical
     prose, not in the code.
