Date prepared: 2026-09-12

PURPOSE
=======
Mechanical census of the live IrOpcode enum
(src/ir-types.h:63-167) against the LLDefMap
classification that the C4 IMPL-B switch arm
implements. This file is the auditable source for:

    N                       = total enum cardinality
    CLASSIFIED_OPCODE_COUNT = rows in the switch
    DEF / USE / NONE counts = partition

Live enum cardinality: 56
  (extracted from src/ir-types.h between
   "typedef enum IrOp {" line 63 and
   "} IrOp;" line 167; the cap-table invariant at
   src/llvm-backend-cap.c:110 ("table has %d rows,
   expected %d (IR_ASM+1)") independently proves
   IR_ASM = 55, hence 56 members total.)

Classification method:
  Each opcode's "dst" field semantics were read from
  the actual irInstrNew() constructor site in
  src/ir.c / src/ir-types.c / src/ir-optimise.c.
  For opcodes that go through a generic binop or
  cast dispatcher (where the literal irInstrNew site
  is inside the dispatcher and not a separate
  helper), the irRedirectLastDst list at
  src/ir.c:288-311 was used as a secondary witness
  for "the opcode has a genuine TMP-defining dst",
  cross-checked against the absence of any
  irInstrNew(IR_X, ...) calls with a non-NULL first
  argument.

Coverage assertions (must hold before any C4
mutation lands):

    classified    == N          (== 56)
    unclassified  == 0
    DEF + USE + NONE        == classified   (== 56)
    DEF ∩ USE                == ∅
    DEF ∩ NONE               == ∅
    USE ∩ NONE               == ∅
    every opcode appears exactly once

RUNTIME PROOF CHANNEL (reviewer correction applied)
====================================================
The reviewer identified that the prior wording mixed
two distinct properties under the heading "41/5/10
are PROVEN by iteration, not asserted by copying
constants":

  A. coverage completeness (mechanically derivable)
     every currently iterated IrOp reaches
       {LL_TMPDST_DEF, LL_TMPDST_USE, LL_TMPDST_NONE}
     no default arm fires for any live enum member
     sum(DEF + USE + NONE) == live enum cardinality

  B. historical partition stability (a frozen
     expectation, NOT mechanically derivable from
     walking the classifier)
     DEF = 41
     USE = 5
     NONE = 10

A is C4's acceptance contract. B is observed
evidence and a snapshot of the classifier's
current partition, NOT acceptance.

The runtime verifier therefore:

  - accepts on coverage completeness ONLY:
      classified == live
      def + use + none == live
  - reports the observed DEF/USE/NONE counts as
    stderr evidence
  - does NOT compare the observed counts to 41/5/10
  - does NOT halt on a partition drift; a drift is
    a future-correction signal for a separate ACT

If 41/5/10 ever drift, the verifier prints the
new observed numbers and continues (it does NOT
halt). A drift in 41/5/10 does not invalidate C4,
because C4's acceptance is "every opcode in the
live enum reaches one of {DEF, USE, NONE}, no
default arm fires, and the partition sums to the
live enum cardinality".

  2. llInstrDefinesTmpDst(ins) becomes a thin
     predicate:

         return llTmpDstClass(ins->op) == LL_TMPDST_DEF;

     This eliminates drift between the coverage
     verifier and the LLDefMap predicate: there is
     one classifier, not two.

  3. llVerifyOpcodeCoverage() iterates the live enum
     and exercises the classifier. It accepts on
     COVERAGE COMPLETENESS only; it does NOT compare
     against the observed 41/5/10 partition values:

         classified = def = use = none = 0;
         for (int op = IR_NOP; op <= IR_ASM; ++op) {
             switch (llTmpDstClass((IrOp)op)) {
                 case LL_TMPDST_DEF:  def++; break;
                 case LL_TMPDST_USE:  use++; break;
                 case LL_TMPDST_NONE: none++; break;
             }
             classified++;
         }
         live = (int)((unsigned)IR_ASM - (unsigned)IR_NOP + 1);
         if (classified != live)
             HALT_C4_OPCODE_COVERAGE_VIOLATED;
         if (def + use + none != live)
             HALT_C4_OPCODE_COVERAGE_VIOLATED;
         /* OBSERVED census (NOT acceptance criteria): */
         fprintf(stderr,
             "[c4-opcode-coverage] live=%d "
             "DEF=%d USE=%d NONE=%d classified=%d\n",
             live, def, use, none, classified);

  4. Negative control: a unit-test variant of
     llTmpDstClass that deliberately omits one current
     opcode (e.g. IR_PHI) must HALT_UNCLASSIFIED_OPCODE_REACHED
     when the verifier iterates the enum. This turns
     the census mechanism itself into a real verifier.

What the verifier does NOT do (per reviewer):

  - It does NOT compare the observed DEF/USE/NONE

  - It does NOT HALT if the partition drifts.

    silently -- the ONLY modification surface for
    partition membership is editing
    `llTmpDstClass()` itself, and any such edit is
    surfaced through a diff of `opcode-coverage.txt`.

PARTITION CHECK (machine-verifiable)
====================================
The PARTITION above is recorded as evidence of the
classifier's current behaviour on the live enum,
NOT as an acceptance contract. The runtime verifier
does not assert these numbers.

  DEF = 41   (evidence; not asserted)
  USE = 5    (evidence; not asserted)
  NONE = 10  (evidence; not asserted)
  ---
  total = 56 == live enum cardinality ✓

The partitions above are mutually exclusive by
construction (the three-way classifier returns
exactly one of {DEF, USE, NONE} for every
non-default arm). Every live enum member appears
in exactly one row by virtue of the switch
exhausting IR_NOP..IR_ASM with a fail-closed
default arm.

    C4 runtime acceptance (encoded in

What the runtime verifier does NOT do (per the
reviewer's contract correction):

  - assert(DEF == 41)
  - assert(USE == 5)
  - assert(NONE == 10)
  - assert(CLASSIFIED_OPCODE_COUNT == 56)
  - assert(IR_OPCODE_ENUM_COUNT     == 56)

The 41/5/10 figures appear in this file only as

FUTURE EXHAUSTIVENESS NOTE
==========================
The runtime fail-closed arm (default: HALT_UNCLASSIFIED_OPCODE_REACHED;)
guarantees that an unknown opcode reaching the classifier at runtime
halts cleanly. It does NOT make a future IrOpcode addition fail at
compile time. Compile-time exhaustiveness is a separate concern
(enumeration sentinel + _Static_assert, or a compiler-enforced
exhaustive-switch language extension) and is intentionally out of C4
scope per the reviewer.

PHASE B SAVE/RESTORE INVARIANT (reviewer correction)
====================================================
The Phase-B helper uses:

    saved = LLVMGetInsertBlock(lc->bld);
    LLVMPositionBuilderBefore(lc->bld, pred_term);
    /* emit zext */
    LLVMPositionBuilderAtEnd(lc->bld, saved);

`LLVMPositionBuilderAtEnd` literally positions at
the END of the basic block. Under our frozen shape
this is safe ONLY because C4 guarantees the PHI is
being lowered at the FRONT of a merge block, BEFORE
any non-PHI instructions have been emitted for this
PHI. This invariant MUST be encoded adjacent to the
implementation as a static assert or comment, and
NOT later generalized.

If a future maintainer moves the PHI emission to a
different point in the merge-block walk, they MUST
re-derive this invariant.
