## P0-2 — Fix B was over-authorized as general IR_PHI support

**Before C1.1:**

```text
IR_PHI = LLVMBC_SUPPORTED      <-- too broad
dispatch arm lowers "any non-null phi pair list"
```

**After C1.1:**

```text
IR_PHI = LLVMBC_SHAPE_DEPENDENT
dispatch arm validates:
  dst != NULL
  dst.kind == IR_VAL_TMP
  dst.type == IR_TYPE_I8
  phi_pairs != NULL && vecSize >= 1
  for each P: P.ir_value != NULL
              P.ir_block != NULL
              P.ir_block in fn->blocks

rejected shapes use a new diagnostic
  LLVM_BACKEND_UNSUPPORTED_PHI_ORTHOGONAL_TO_CORE
(the legacy LLVM_BACKEND_UNSUPPORTED_PHI is preserved for
 future use if the backend ever fully retracts IR_PHI)
```

Full contract: c1.1/phi-onepass-safety.txt §"Future PHI
producers: the SHAPE_DEPENDENT guard".

## P0-3 — one-pass PHI lowering safety was not proven

**Before C1.1:**

```text
pseudocode: immediate llLowerValue + LLVMAddIncoming
no proof that incoming values are bound at that moment
```

**After C1.1:**

Mechanically proven by pre-ordering argument:

```text
For every IR_PHI in the current IR:
  for each (ir_block, ir_value) incoming pair P:
    index(P.ir_block) < index(merge_block)
      in fn->blocks linked-list iteration order
```

The pre-ordering is enforced by the frontend
(src/ir.c:531/562/588: `irFnAddBlock` of predecessors
precedes the merge block add) and confirmed by the G3.ir.txt
captured at C1.

Two-phase lowering is documented as the bounded fallback for
future producers that may violate the invariant.

Full proof: c1.1/phi-onepass-safety.txt.

## P1 — negative control was a frontend-crash-as-evidence

**Before C1.1:**

```text
P12: "V used as pointer -> compiler CRASH"
  (no source-level witness; a crash is not an oracle)
```

**After C1.1:**

Mechanical witness GN4_neg.HC:

```c
I64 GN4(I64 **p, I64 x) {
    I64 *v = *p;
    *v = x;            // IR_STORE_DEREF(dst=v_ptr, r1=x)
    v = *p;
    *v = x;
    return 0;
}
```

Produces IR with `store* %l6 ptr local, ...` where `dst == V`.
Today, the discriminator rejects this with a NAMED diagnostic
(`OPTION_W_INELIGIBLE`), not a crash. The witness is
reproducible via `hcc --install-dir --dump-ir`. C2-A must
verify that the witness is still rejected after the widening.

Full contract: c1.1/negative-control.txt.
