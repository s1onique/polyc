THE PRODUCTION-CAUSAL MUTATION
=============================

THE FROZEN MUTATION
-------------------
  Token '-' maps to AST_UN_OP_PLUS instead of AST_UN_OP_MINUS.

  Exactly ONE line of the component changes, in a SCRATCH COPY:

    pristine:  if (token_value == 45)  return 5;   // '-' -> AST_UN_OP_MINUS
    mutated:   if (token_value == 45)  return 4;   // '-' -> AST_UN_OP_PLUS

WHY THIS PROVES THE DELEGATION IS LOAD-BEARING
-------------------------------------------
  The A, B and C compilers are THREE ACTUAL PRODUCTION COMPILERS,
  each linking a different unary subject object.  Each compiler
  compiled the SAME frozen observation program, and the program was
  EXECUTED.

  A produced UNARY_MINUS_RESULT=-7  (the pristine classification).
  B produced UNARY_MINUS_RESULT=7   (the mutated classification:
    the parser classified '-' as unary PLUS, so -x evaluated to +x).
  C produced UNARY_MINUS_RESULT=-7  (the restored classification).

  The three OTHER observations (unary plus, logical not, bitwise not)
  are IDENTICAL in A, B and C.  The mutation is therefore SPECIFIC:
  it changed the '-' classification and nothing else.

  If the production parser had NOT consulted the PolyC component, B
  would have produced the same output as A and
  B_OUTPUT_DIFFERS_FROM_A would have been NO.  It is YES, so the
  production path demonstrably depends on the PolyC decision.

THE TRACKED COMPONENT WAS NOT MUTATED
----------------------------------
  TRACKED_COMPONENT_SHA256_BEFORE == TRACKED_COMPONENT_SHA256_AFTER
  (both 26a9b4578d3dc6301a26df5f6d8ee3d8bb4326869aa1165949112aa9c44065fb)

  The mutant lives in build/slice05-mut/.  The tracked file was never
  written to.

THE OBSERVATION CHANNEL
----------------------
  stdout, as plain decimal numbers.  The observation does NOT rely
  on a process exit code: an exit status truncates a negative value on
  many hosts, and the mutation's whole point is to turn a NEGATIVE
  observation into a POSITIVE one.

  No host-specific nondeterminism was observed or expected: the
  program performs only integer arithmetic and writes four fixed-format
  lines, with no address, timestamp, hash-order iteration or
  filesystem access in the observed output.
