NC-P04 -- A NON-BYTE-IDENTICAL SUBJECT SUBSTITUTED
===================================================

THE CONTROL
------------
COMMAND=make parser-slice05-provenance-controls
OUTPUT:
  SLICE05_FORGERY=CASE-NC-P04 a non-byte-identical subject substituted
    SLICE05_FORGERY=CASE-NC-P04 PROVENANCE_VERDICT=REJECTED

  The recorded OUTPUT_OBJECT_PATH of the g3 row points at a COPY of
  the g3 object with one extra byte appended.  The substitute is a
  VALID object file -- it still links -- but it is NOT byte-identical
  to the object the witness claims.

  MUTATION_TARGET=OUTPUT_OBJECT_PATH

THE REJECTION
--------------
  MUTANT_VERDICT=REJECTED
  NON_TARGET_FIELDS_UNCHANGED=YES

  THE VERIFIER OUTPUT:
COMMAND=cat build/slice05-nc/nc-p04.txt
  GENERATIONS_PRESENT=4
  GENERATION_ROWS=4
  STAGE_LABELS_MATCH=4
  G3_OBJECT_IDENTITY_MISMATCH g3 recorded object sha [27075194e1d3ff94703b51459cc3e5c8ea472747ea1f255a451a97f44b416e72] but the live object hashes to [6338e539b995a351ffd8463b72e5575ad53a799bda88dfea386825416a4ca0a3]
  ALL_REQUIRED_RECEIPTS_PRESENT=4
  DUPLICATE_NONCE_COUNT=0
  GENERATIONS_VERIFIED=4
  PROVENANCE_VERDICT=REJECTED

  The rejection is an EXACT OBJECT-IDENTITY MISMATCH: the recorded
  object sha256 is compared against the LIVE sha256 of the object the
  witness names.  This is the case that a BYTE-ONLY comparison of
  the generations could not see, because the substituted object is
  still a valid object.

THE PRISTINE RECHECK
-------------------
  PRISTINE_VERDICT=PASS
  PRISTINE_RECHECK=PASS
  PRISTINE_MANIFEST_VALID=YES
