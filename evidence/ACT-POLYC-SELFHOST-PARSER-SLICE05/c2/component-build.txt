THE COMPONENT BUILD
===================

THE STAGE0 COMPILER BUILDS THE SUBJECT
--------------------------------
COMMAND=make build/parser-ast-unary-subject.o
OUTPUT:
SLICE05_AST_UNARY_SRC = tools/bootstrap/selfhost-parser-slice05.HC
SLICE05_AST_UNARY_OBJ = ./build/parser-ast-unary-subject.o
  ./build/host-stage0/hcc --install-dir=./build/bootstrap-prefix \
    -c tools/bootstrap/selfhost-parser-slice05.HC \
    -o build/parser-ast-unary-subject.o
  SLICE05_AST_UNARY_OBJECT=build/parser-ast-unary-subject.o
BUILD_EXIT_CODE=0

  The subject is compiled by the STAGE-0 compiler, exactly like the
  parser-padding, control-flow-token, operator-precedence and AST
  binary-operator subjects, so the component does not depend on the
  production compiler that it is about to serve.

THE EXPORTED SYMBOL
-------------------
COMMAND=nm build/parser-ast-unary-subject.o | grep BootstrapAstUnary

  Makefile rule FAILS the build if the symbol is absent.

THE FOUR GENERATIONS ARE BYTE-IDENTICAL
--------------------------------------
COMMAND=make parser-slice05-generations
OUTPUT:
  G1_OBJECT_SHA256=27075194e1d3ff94703b51459cc3e5c8ea472747ea1f255a451a97f44b416e72
  G2_OBJECT_SHA256=27075194e1d3ff94703b51459cc3e5c8ea472747ea1f255a451a97f44b416e72
  G3_OBJECT_SHA256=27075194e1d3ff94703b51459cc3e5c8ea472747ea1f255a451a97f44b416e72
  G0_OBJECT_SHA256=144c9836ba79125bd973f9faefe05b259e9efaa1e8bc7babc5c44de007de7253

  G1, G2 and G3 are BYTE-IDENTICAL, and each was produced by a
  DIFFERENT compiler.  That is precisely why the provenance witness
  (not the object bytes) is what detects a substitution.
