THE FRESH-TREE LINK INTEGRITY
============================

THE BUILD WAS FROM A PRISTINE TREE, NOT THE WARM TREE
--------------------------------------------------
COMMAND=git archive HEAD | tar -x -C /tmp/slice05-fresh
  (the tree was materialised from the committed sources, then the
   C2 production changes and the five qualified subject objects were
   copied in)
COMMAND=cd /tmp/slice05-fresh && make production-hcc
BUILD_EXIT_CODE=0
  PRODUCTION_PADDING_AUTHORITY=POLYC
  PRODUCTION_AST_BINOP_AUTHORITY=POLYC

  The build ran in a SEPARATE directory with its OWN CMake build
  tree and its OWN object files.  No object from the warm tree was
  reused: the compiler was compiled from source there.

THE DUPLICATE-SYMBOL CHECK
-------------------------
COMMAND=nm ./hcc | grep -E "_Bootstrap[A-Za-z]+" | awk "{print \$3}" | sort | uniq -c | awk "\$1>1"
  (no output means NO symbol name appears more than once)

  DUPLICATE_BOOTSTRAP_SYMBOLS=0

  This is the check SLICE04 exposed as a defect in its own
  qualification link inputs: a subject that was linked TWICE
  produced a DUPLICATE SYMBOL conflict.  Here every subject is
  linked exactly once and the count is zero.
