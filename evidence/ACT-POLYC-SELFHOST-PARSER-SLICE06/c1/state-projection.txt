-------------
  field        stmt->kind

THE LIVE PROJECTION SITE
------------------------
COMMAND=grep -n 'parseSwitchArmTerminates' src/parser.c
  1517:static int parseSwitchArmTerminates(int kind)
  1535:    return (int)BootstrapSwitchArmTerminates((long long)kind);
  1654:        if (parseSwitchArmTerminates((int)stmt->kind)) break;

The C side reads EXACTLY ONE host field -- stmt->kind -- copies it as
an I64, passes it to the PolyC component, receives ONE I64 back, and
acts on it by executing the `break` itself.

THE DECISION MAKES NO HOST-GRAPH WRITE, NO ALLOCATION, NO CALLBACK,
NO RECOVERY TRANSFER AND NO DIAGNOSTIC.  The single effect on the host
is the `break` that the C side executes, which the C side would have
executed anyway.

THE PROJECTION IS THEREFORE:

  C-owned source values            stmt->kind (one AstKind enum value)
         |
         v
  explicit scalar/copy projection   stmt->kind -> I64 kind
         |
         v
  PolyC decision                    I64 kind -> I64 terminate (0 or 1)
         |
         v
  bounded result                    one bounded boolean
         |
         v
  C-owned mutation/orchestration    if (terminate) break;   (the C side)

NO OPAQUE POINTER CROSSES: there is no void *, no encoded pointer and
no callback table.  THE JMP_BUF DOES NOT MOVE.

THE ABI IS BOUNDED
------------------

The component is a TOTAL function over the I64 domain: every I64 maps
to exactly one of {0, 1}.  There is no error return, no exception, no
diagnostic and no recovery interaction.

THE CAST CHAIN IS EXACT
-----------------------
The legacy C wrapper is `int(int)` and the PolyC ABI is
`I64 -> I64`.  The chain is

  (int)stmt->kind -> (long long)kind -> (long long)ast_kind -> (int)result

The AstKind values are small non-negative integers and the result is a
boolean, so every step is exact and no value is truncated.  The I64
domain is fully covered by the component regardless, because the
component's OWN parameter is an I64 and its comparisons are against
the six exact enum values.

THE OUT-OF-ENUM DOMAIN IS NOT TRUNCATED
---------------------------------------
The legacy condition does NOT range-check the kind: it compares the
value against six constants and terminates the arm if any of them
matches.  An out-of-enum value matches none of them, so the arm
CONTINUES.  The PolyC component reproduces this exactly: it has NO
range check, so the out-of-enum probes -4..0 and 300 all return 0,
exactly as the legacy object-level oracle reports.
