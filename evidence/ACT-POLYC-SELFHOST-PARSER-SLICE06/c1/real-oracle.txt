THE OBJECT-LEVEL G0 ORACLE (THE STRONGER FORM)
==============================================

The predecessor's frozen oracle contract (c2/selected-oracle-contract.md
section 4) required the successor to STRENGTHEN the source-bound
extraction to the object-level form:

  * compile src/parser.c with the delegation OFF and extract the
    decision from that OBJECT, so the oracle comes from the real
    production translation unit rather than from a copy; and
  * verify that the delegation-ON object does NOT contain the legacy
    condition.

This file records that STRENGTHENED oracle.

THE G0 OBJECT
--------------
COMMAND=cc -std=c99 -O2 -Isrc -c -o build/slice06-parser-legacy.o src/parser.c
  (exit 0)

This is the ACTUAL production translation unit src/parser.c, compiled
WITHOUT HCC_USE_SELFHOST_PARSER_SWITCH_ARM, so the legacy
arm-termination condition -- the byte-identical legacy source -- is the
code that executes.

COMMAND=nm build/slice06-parser-legacy.o | grep '_ParserLegacySwitchArmTerminatesOracle'
  0000000000003254 T _ParserLegacySwitchArmTerminatesOracle

COMMAND=nm build/slice06-parser-legacy.o | grep -c 'BootstrapSwitchArmTerminates'
  0

The object defines the legacy decision's wrapper and does NOT reference
the PolyC component: the delegation is genuinely OFF.

THE MAKEFILE RULE FAILS CLOSED ON THAT
---------------------------------------
The rule build/slice06-parser-legacy.o in the Makefile FAILS the build
if the object references _BootstrapSwitchArmTerminates, so the "the
delegation was not off" condition cannot pass silently.

  SLICE06_LEGACY_ORACLE=./build/slice06-parser-legacy.o (delegation OFF:
  the real legacy body is executed)

================================================================
COMMAND=nm build/CMakeFiles/hcc.dir/parser.c.o | grep 'BootstrapSwitchArmTerminates'

The G0 object contains the REAL decision: it subtracts 0x102 (=258,

terminating kinds.

NOTE ON WHEN THIS WAS MEASURED
-------------------------------
The production object above was measured on the WORKING TREE that
carries both the C1 oracle seam and the C2 production wiring, because
the object-level G0 oracle and the delegated production object must
coexist for the differential to be meaningful: a differential run
against the delegated build would compare the PolyC component against
itself and would be vacuous.

The C2 commit carries the production wiring (the CMake selector and
the call-site delegation).  The C1 commit carries ONLY the oracle
seam: the decision function with its delegation `#ifdef` and the
legacy wrapper.  With the macro UNDEFINED -- which is the C1 tree's
state -- the C1 tree's production object still contains the LEGACY
condition, and the C2 commit's tree does not.

The C1 tree's production object is therefore NOT yet free of the
legacy condition; the C2 commit is what retires it.  The C1 claim is
only that the G0 ORACLE is object-level, that it agrees with the
frozen extraction, and that the delegation mechanism (the `#ifdef`
inside parseSwitchArmTerminates) is in place.  The production
authority transfer is a C2 claim, verified in c2/production-delegation.txt.

  LEGACY_CONDITION_IN_G0_OBJECT=YES
