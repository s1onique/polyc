THE DELEGATION IS NOT A DUPLICATION
------------------------------------
At the call site, the legacy condition was:

  if (stmt->kind == AST_COMPOUND_STMT || stmt->kind == AST_CASE ||
          stmt->kind == AST_DEFAULT || stmt->kind == AST_BREAK || stmt->kind == AST_RETURN
          || stmt->kind == AST_GOTO) break;

and it now reads:

  if (parseSwitchArmTerminates((int)stmt->kind)) break;

The C side does NOT evaluate the same condition before, after or
alongside the delegation.  There is no shadow call and no fallback to
C.  The disassembly above PROVES this: the active production object
contains no comparison at all.

THE C SIDE STILL OWNS THE BREAK
-------------------------------
The PolyC component decides; the C side acts.  The `break` that leaves
the arm loop is still executed by the C side, and the C side still
owns the AST graph, the allocation, the diagnostics, the recovery point
and the token stream.

THE BUILD SELECTOR IS VERIFIED, NOT ASSERTED
---------------------------------------------
The dedicated selector HCC_USE_SELFHOST_PARSER_SWITCH_ARM is wired
into src/CMakeLists.txt exactly as the five already migrated
authorities are, and the SLICE04 generic verifier
(src/cmake/VerifyAstTokenMapObject.cmake) is REUSED READ-ONLY with
the expected symbol BootstrapSwitchArmTerminates and the target object
format passed in EXPLICITLY.

The verification is a custom TARGET, not an OUTPUT-producing custom
command, so the verification command ALWAYS runs and a stale stamp can
never decide that the verification is unnecessary.  The production
compiler is never linked without a verified PolyC switch-arm
authority.

A missing component is a HARD CONFIGURE ERROR, never a silent legacy
fallback.
