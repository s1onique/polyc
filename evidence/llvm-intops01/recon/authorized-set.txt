=== Outcome E (per ACT §36) ===

> If fresh recon shows the ACT premise is stale:
>     HALT_RED_NOT_REPRODUCED
>     and advance to BYTE-MEMORY01 instead of manufacturing work.

The B0 demand recon has demonstrated that no additional scalar integer
operations are required to implement the B0 lexer. The existing LLVM
backend, as proven by LLVM-SPIKE01-RESUME01 (PASS=18), CORE04-RESUME01,
and MEMORY01 (PASS=6), already supports every integer operation the
smallest credible B0 lexer needs:

    cursor + 1                      -> IR_IADD (SUPPORTED)
    cursor - tok_start              -> IR_ISUB (SUPPORTED)
    v * 10 + digit                  -> IR_IMUL + IR_IADD (SUPPORTED)
    c >= '0' && c <= '9'            -> IR_ICMP (SUPPORTED)
    if/while control flow           -> IR_BR / IR_CMP_BR (SUPPORTED)
    function calls                  -> IR_CALL (SUPPORTED)
    return value                    -> IR_RET (SUPPORTED)
    I64 pointer cursor load/store   -> IR_LOAD_DEREF / IR_STORE_DEREF (via MEMORY01, SUPPORTED)

Note: this is the I64-typed cursor load/store path. The actual B0
source-text path needs U8 *src + index arithmetic (*(src + n)) which
is BYTE-MEMORY01 / GEP01 territory, NOT part of the INTOPS01 proof.
The recon probe (b0_lexer_shape_probe.HC, b0_digit_accum.HC) only
exercises I64 *src. INTOPS01 closes on the I64 substrate being
sufficient; the byte + indexed-addressing substrate is the next ACT.

Adding bitwise, shift, divide, remainder, or conversion ops to the
LLVM backend at this point would violate F8 (no speculative abstraction)
and the ACT's own outcome-E decision rule.
