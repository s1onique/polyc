ROOT CAUSE / FINDING
  Neutral IR already carried IR_TYPE_I8 (signedness discarded by
  irConvertType). Backend admitted only I64 access for
  IR_LOAD_DEREF / IR_STORE_DEREF; IR_ZEXT / IR_SEXT did not have the
  I8 -> I64 promotion shape; IR_TRUNC rejected all shapes including
  I64 -> I8 narrowing for byte-local storage. This ACT admits the
  bounded minimum byte path.

RED
  Five principal RED fixtures now compile to verifiable LLVM IR
  emitting load i8 / zext i8 -> i64 / sext i8 -> i64 / trunc i64 -> i8
  as appropriate. Negative control red_i16_trunc_negative.HC is
  rejected with the named LLVM_BACKEND_UNSUPPORTED_CONVERSION
  diagnostic. pos_byte_compare_simple.HC passes llvm-as + opt verify.

IMPLEMENTATION
  src/llvm-backend-cap.c: IR_LOAD_DEREF, IR_ZEXT, IR_SEXT, IR_TRUNC
    rows updated to SHAPE_DEPENDENT with explicit byte-shape notes;
    IR_STORE_DEREF unchanged (I64 only; byte store DEFERRED).
  src/llvm-backend.c: llTypeSupported / llParamTypeSupported / llType
    admit IR_TYPE_I8 / IR_TYPE_U8; IR_LOAD_DEREF byte shape emits
    load i8, ptr; IR_STORE local I8; IR_ZEXT / IR_SEXT / IR_TRUNC
    SHAPE_DEPENDENT; IR_ICMP / IR_IADD / IR_ISUB / IR_IMUL narrow
    I64 to i8 for byte ops then zext to i64; IR_RET truncates
    widened I64 back to i8.
