------------------------------------------------------------
C1 dump-header format (informational, not a fix)
------------------------------------------------------------

The 5 dump files (i64idx.dump, read0.dump, read2.dump,
readat.dump, twodigits.dump) each contain exactly one
trailing-whitespace line:

    ===== After basic optimisations =====

The trailing space at the end is emitted by the canonical
PolyC dump printer in src/ir.c; it is part of the
canonical dump format and is therefore expected.

The blank-line-at-EOF in the same files is the canonical
dump printer's last newline followed by an additional
empty line. Also expected.

These dumps are EVIDENCE; they capture the real
--dump-ir output, not a cleaned-up version.

------------------------------------------------------------
C3/C4 heredoc format (informational, not a fix)
------------------------------------------------------------

The 6 heredoc-written summary files were produced with
the shell pattern:

    cat > foo.txt <<'EOF'
    ...
    EOF

which always ends the file with the final newline of
the heredoc contents. When the last visible line was a
blank line in the source, the file ends with TWO newlines,
producing the `new blank line at EOF` diagnostic.

Again, evidence; not a defect of substance.
