Defect: the `if (cond->type != IR_TYPE_I8)` early-out uses the IR
type as a proxy for predicate semantics. When cond already has type
IR_TYPE_I8 (regardless of producer), the entire truthiness-
normalization block is skipped.

The `isa_bool` fallback at line 111 only triggers for the very
common but fragile case where the previous instruction in the same
block is an IR_ICMP/IR_FCMP whose dst equals cond. It does NOT
catch:
  - cross-block branch callers (try L1930, switch L2358/L2368/L2377)
  - call-return I8 paths (L538, L564 pass left directly)
  - any IR_CALL returning IR_TYPE_I8 (most direct demonstration
    of the bypass)
  - logical ! / && / || chain operands

This ACT's principal RED (red-01-identity-bypass.HC) demonstrates
that IR_CALL returning IR_TYPE_I8 followed immediately by IR_BR with
that value as the condition reproduces the bypass:
    call     %t9 i8 tmp, Identity  ; line 4
    br       %t9 i8 tmp, bb5, bb6  ; line 4
with NO cmp_ne between them.
