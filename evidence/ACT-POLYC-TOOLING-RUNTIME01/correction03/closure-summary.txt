DEFECTS FIXED IN CORRECTION03:

  P0 BUILD INTEGRATION (REAL PRODUCTION SEAM)
    - CMake execute_process(COMMAND ...) does NOT invoke a shell
      on POSIX. The CORRECTION02 install step had
      `ar r ... && ranlib ...` which passed `&&` as a literal
      argv member to ar (interpreting `&&` and `ranlib` as
      member filenames). The CORRECTION02 GREEN runtime was
      therefore built via developer-side shell, NOT the
      committed install path.
    - CORRECTION03 splits into separate execute_process calls
      and adds COMMAND_ERROR_IS_FATAL ANY.
    - Mandatory witness: fresh build dir, cmake configure,
      cmake --install (exit=0), installed libtos.a contains
      _Errno + _PollIntr + _ReadIntr + _WaitPidIntr +
      _SpawnAndCapture, runtime01-selftest compiled against
      installed prefix runs 18/18 PASS, binary dynamically
      links to the installed libtos.0.0.1.dylib.

  P1 PLATFORM CONTRACT
    - CORRECTION02 passed -D__APPLE__ unconditionally, lying
      about the platform on every host. CORRECTION03 confines
      -D__APPLE__ and errno_shim.c compilation to the if(APPLE)
      branch, and message(FATAL_ERROR)s on non-Apple.
    - hcc's preprocessor does not currently short-circuit body
      text under a `defined()` predicate whose macro is unset;
      removing the `#if defined(__APPLE__)` guard from
      tooling.HC and enforcing the contract one level up
      (CMake) is the minimal honest fix. Documented in
      tooling.HC inline comments.

  P1 EVIDENCE TRUTH (AC MATRIX)

      Linux/Windows portability moved to residue-correction03.txt
      as P1 (Linux ACT-POLYC-TOOLING-LINUX-PORT01) and P2
      (no ACT opened).

  P1 DOC: WAITPIDINTR RETURN VALUE
    - Comment said "0 on reap, -1 on real failure" but the
      implementation returns the actual waitpid(2) value
      (>=0 on success). Corrected to be precise.

  P1 EINTR EVIDENCE REINFORCED
