------------------------------------------------------------
ROOT CAUSE / FINDING
------------------------------------------------------------

  Two defects in src/holyc-lib/tooling.HC::SpawnAndCapture:

  P0 (blocks decision): the original implementation drained
     stdout fully before opening stderr. When the child writes
     >64 KiB to stderr while keeping stdout open, the stderr
     pipe fills, the child blocks in write(2), and the parent
     blocks in read(out_fd) because stdout is still open in
     the child — a permanent deadlock.

  P1 (sub-bug, found and fixed in CORRECTION01): the first
     fix attempt closed the read-end on POLLHUP without
     draining. POLLHUP fires when the WRITER closes, but the
     kernel may still buffer bytes that were enqueued before
     the close. Closing on POLLHUP loses those bytes. Final
     fix: on any revents (POLLIN | POLLHUP | POLLERR), attempt
     read; only close when read returns 0 (true EOF).
