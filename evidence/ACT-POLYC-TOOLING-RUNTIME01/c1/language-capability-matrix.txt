Hidden dependency check (ACT §10)
------------------------------------------------------------

The ACT forbids making STRUCT01 / ARRAY01 hidden
prerequisites. The proposed ProcessResult API
(exit, stdout, stderr) does NOT require a new struct:

  - exit_code : I64 (scalar)
  - stdout    : U8 *   (already a U8 pointer in existing
                          FileRead / Shlurp)
  - stderr    : U8 *   (same)

The argv API uses U8 *args[] which is already used in
src/tests/lsp/run_lsp_tests.HC:402-405:

    U8 *args[3];
    args[0] = g_hcc;
    args[1] = "-lsp";
    args[2] = NULL;
    execv(g_hcc, args);

This is an existing language form, not a new compiler
feature. The NULL terminator at args[2] is conventional
execv usage; it is the literal NULL token, not a new
language feature.

Conclusion: NO hidden STRUCT01 or ARRAY01 dependency.

------------------------------------------------------------
First-harness minimum primitive set (per ACT §9)
------------------------------------------------------------

Derived from llvm-gep01-test.sh semantics:

  Process:
    - SpawnAndCapture(argv, &out, &err) -> I64 exit
       (no shell; direct exec; pipes for capture)
    - Wait(pid) -> I64 exit code, distinguishes abnormal
       termination
  File:
    - ReadAll(path) -> U8* (already FileRead)
    - WriteAll(path, buf, len) -> Bool (already FileWrite)
    - FileExists(path) -> Bool (Stat wrapper)
    - Remove(path) (already Rm)
    - TmpFile(template) -> I32 fd + U8 *path (mkstemp)
  Text:
    - Contains(haystack, needle) -> Bool (new, thin
       wrapper over libc strstr)
  Verdict:
    - VerdictNew() / VerdictPass(verdict, name) /
       VerdictFail(verdict, name, msg) /
       VerdictRc(verdict) -> I64
       Aggregate with global counters is also acceptable
       (the ACT does not require an OO API).

  Existing HolyC facilities sufficient:
    - StrCmp, StrLen, StrPrint, StrOcc
    - MAlloc, Free
    - Exit
    - FileRead, FileWrite
    - Rm, Cd, Pwd
    - System, Sh (EXISTS_BUT_WRONG_ABSTRACTION:
       routed via /bin/sh -c; must NOT be used by the
       new tooling runtime)

------------------------------------------------------------
Failure layer (ACT §11)
------------------------------------------------------------

The first RED probe attempts:

    SpawnAndCapture("/bin/printf", "hello", &out, &err)

Expected behaviour AFTER C2:

    out == "hello"
    err == ""
    exit == 0

In the current tree (C1), the attempt fails because
SpawnAndCapture is not defined. The actual observed
failure is at PARSER layer: unknown identifier
"SpawnAndCapture".

Per ACT §11: this is an acceptable RED — the failure
layer is parser/missing-symbol, not a fixture defect
and not silent-success.
