## DEFECT-5 (P2): ac40-transform.tsv byte-description misleading

The CORRECTION01 ACT's `c2/ac40-transform.tsv` describes the
byte-level correction as:

  original_eof_byte  = 0x0a (LF)
  corrected_eof_byte = (no trailing LF)

For a Git `"new blank line at EOF"` diagnostic, the actual
byte-level interpretation is:

  original_suffix  = 0x0a 0x0a   (one LF ending content + one extra LF for the blank line)
  corrected_suffix = 0x0a         (one LF ending content; no extra blank line)

The TSV's `(no trailing LF)` description is misleading:
removing the final LF entirely would create a different
"no newline at end of file" diagnostic. The prose elsewhere in
the CORRECTION01 evidence correctly says "remove the trailing
blank line"; only the TSV byte column is misleading.

Empirical reproduction (using the recon ACT's closed file
content):

  $ tail -c 4 evidence/.../c1/prior-negative-score-red.txt | od -c | head -1
    ... two 0x0a bytes at end (the extra blank line LF)

  $ git diff --check 7adb9e8 -- evidence/.../c1/prior-negative-score-red.txt
    evidence/.../c1/prior-negative-score-red.txt:37: new blank line at EOF.

The diagnostic message literally says "new blank line", which
corresponds to the extra 0x0a byte, not to removal of the
final 0x0a.

Forward-fix: c2/ac40-transform-v2.tsv reproduces the corrected
byte-level description using `original_suffix` and
`corrected_suffix` columns.
