Complete chain:
  IR_FCMP (kind)
    -> x86_64CcFor(kind, 1)  returns "e"|"ne"|"b"|"be"|"a"|"ae"
    -> text:  ucomisd %xmm1, %xmm0
    -> text:  set<cc> %al
    -> text:  movzbq %al, %rax
    -> x86_64SpillDst stores %rax to dst's location

Result location: dst is stored in IR_LOC_REG %rax (GPR) for the duration
of this instruction; later spill/load takes it from %rax to its home
slot or pinned register. Boolean representation is therefore an 8-bit
byte in %al zero-extended to a 64-bit GPR.

UCOMISD operand order: AT&T ucomisd src, dst compares dst - src
(numerical subtraction with flags set per UCOMISD table).
PolyC emits "ucomisd %xmm1, %xmm0", which means
flags <- (xmm0 cmp xmm1) at operand precision. So:
  - xmm0 = first source (instr->r1)
  - xmm1 = second source (instr->r2)
  - flags reflect (r1 cmp r2) from the natural numeric ordering.
  - This matches the semantic that `r1 OP r2` reads
    "first-source cmp second-source" with the same direction the
    SETcc suffix expects for an unsigned compare.
