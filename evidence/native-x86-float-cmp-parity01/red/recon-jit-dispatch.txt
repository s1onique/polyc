AOT/JIT parity (R2 outcome):

  Both paths use the same logical table {e, ne, b, be, a, ae} mapped
  to the same X86Cc enum values {E, NE, B, BE, A, AE}. AOT emits raw
  AT&T text via `aoStrCatFmt`; JIT uses direct-emit encoders. The
  defect surface is identical: neither path handles PF for the four
  broken predicates.

  Both paths use identical operand order: xmm0 = r1, xmm1 = r2,
  flags reflect (r1 cmp r2). UCOMISD operand ordering matches.

  No shared helper exists between AOT and JIT for SETcc composition.
  Both emit a single `setcc %al` followed by `movzbq %al, %rax`.
  Both need to be modified in parallel.

  jitEmitSetCC currently only takes (AsmEnc *, IrCmpKind, int) and
  has no path to issue a second SETcc or a byte ALU. This is the
  encoder layer that must be extended (or bypassed) to implement the
  four unordered-masking sequences.

  x86_64_enc_setcc_al already supports arbitrary cc values 0..0xF,
  so `setp` and `setnp` are reachable with no new encoder.
