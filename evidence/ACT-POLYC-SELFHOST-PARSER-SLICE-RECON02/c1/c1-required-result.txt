H3_CALC_UNION_SIZE=CONFIRMED_ELIGIBLE_ON_STATE_BOUNDARY
  src/parser.c:397..408.  Reads cls_field->type->size only; writes only
  the local `int max`; NO host-graph write.  R0=0 confirmed.
  Integer-promotion details preserved for the C2/C3 analysis:
    - `int max = 0;` (signed int)
    - `AstType.size` is declared `int` (src/ast.h:158), so
      `if (max < type->size)` is a SIGNED int vs SIGNED int comparison --
      there is no unsigned promotion and no usual-arithmetic-conversion
      hazard here.  Both operands are int, so the comparison is exact for
      the full int range.
    - `return max;` with a `u32` return type: the signed int is converted
      to u32.  A NEGATIVE `max` (possible only if a field carried a
      negative size) would convert to a large u32.  The C side therefore
      has a signedness edge that a naive `max()` over u64 sizes would
      silently lose.
    - EMPTY LIST => returns 0 (the loop body never runs).
    - A field of size 0 (e.g. a `U0 body` placeholder) does not change
      `max` because `0 < 0` is false.
  Its production seam is a FUNCTION-POINTER argument
  (u32 (*computeSize)(List *)) at src/parser.c:722, which is narrower
  than CAND-001's ordinary call sites.
