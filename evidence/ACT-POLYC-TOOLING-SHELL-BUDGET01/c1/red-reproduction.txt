R2  Existing shell-loc gate prevents growth but does not
    permanently ratchet a file downward after shrink.
----------------------------------------------------------------

  Demonstration: if scripts/quality/inventory.sh (19 LOC) were
  shrunk to 10 LOC tomorrow, shell-loc-gate.sh would still
  enforce a 50-LOC new-file cap (because the file has no
  baseline entry).  Its 19-LOC baseline would NOT be updated
  to 10; the per-file cap would not ratchet downward to a
  permanent 10.  The file could later grow back to 19 with
  no rejection.

  More concretely: shell-loc-gate.sh reads
  evidence/ACT-POLYC-TOOLING-SHELL-BUDGET01/c1/../SHELL-INVENTORY01/c1/baseline.txt
  from a fixed path and never rewrites it.  There is no
  per-file ratchet mechanism; the baseline is an inert
  snapshot.

  RESULT: R2 RED REPRODUCED.

    of a previously deleted migrated Bash harness.

    --- resurrected stub LOC = 30 ---

    FAIL  NEW   scripts/quality/factory-halt-classification-test.sh  cur=182 > 50
