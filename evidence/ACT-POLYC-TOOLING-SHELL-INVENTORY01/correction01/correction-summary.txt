output of inventory.sh during the original C1 session,
captured via a tee that was truncated mid-stream. The
authoritative output of inventory.sh has 22 rows (one per
shell file in scripts/quality).

The ACT's AC03 ("inventory.sh produces a row per shell
file in scripts/") was FAIL at the time of CLOSE because
the committed inventory.txt only contained 5 of 22 rows.

The CLOSE packet's claim "AC03 PASS" was therefore
incorrect. The CORRECTED state is:

  - inventory.sh IS capable of producing 22 rows
    (verified in this correction by re-running it into
    correction01/inventory-authoritative.txt, which
    contains all 22 rows).
  - The historical c1/inventory.txt artefact is BROKEN;
    it contains 5 rows because of tee buffering at C1.
  - AC03 should have been FAIL at C1; CLOSE should have
    not claimed PASS.

Correction:

P0 arithmetic defect #2: grandfathered LOC was misreported
------------------------------------------------------------

The c2/closure-summary.txt and the ROADMAP handoff
claimed:

  Grandfathered shell debt: 5,710 LOC across 19 files.

The arithmetic was wrong. The committed baseline.txt has
20 files totalling 6,131 LOC. Only one baseline file is
<=50 LOC:

    scripts/quality/llvm-closure-status-check.sh = 21 LOC

Therefore:

    grandfathered files (pre-ACT, >50 LOC) = 19
    grandfathered LOC (pre-ACT)            = 6,131 - 21
                                           = 6,110
                                           (not 5,710)

The error was a 400 LOC under-count. Most likely cause:
subtracting 21 twice (the "small file exception") in the
closure summary calculation.

Correction:

    scripts/quality/llvm-closure-status-check.sh = 21 LOC
                                                    ^^^
                                         (the ONE pre-ACT
                                          file <=50 LOC)

    Pre-ACT baseline:
      total files        = 20
      total LOC          = 6,131
      files <=50 LOC     =  1   (21 LOC)
      grandfathered      = 19
      grandfathered LOC  = 6,110

    Current tree (post-ACT):
      total files        = 22   (added inventory.sh +
                                 shell-loc-gate.sh)
      total LOC          = 6,176
      files <=50 LOC     =  3   (21 + 19 + 26)
      grandfathered      = 19   (unchanged)
      grandfathered LOC  = 6,110 (unchanged)

P2 hygiene defect #3: GEP01 CORRECTION01 EOF blemish
------------------------------------------------------------

The new digest also reported:

  evidence/ACT-POLYC-LLVM-GEP01/correction01/correction-summary.txt:152
    new blank line at EOF

This is a heredoc artefact (the shell <<EOF always ends
with the last newline; if the source body ended with a
blank line, the file ends with TWO newlines). It is
documented here for completeness but is not a substantive
defect and the historical commit d0e7f4f is preserved.
