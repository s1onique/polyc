=== ACT-POLYC-LLVM-CORE03-CORRECTION05 RED M1: literal LF in runtime payload (REAL hcc emitter) ===

Reviewer's P0-2 against CORRECTION04: the prior RED witness
(red-m2-literal-lf-in-note.txt) was synthetic. The reviewer
correctly observed that the C emitter can produce a real LF
byte at runtime via the "\n" escape sequence:

    .note = "line1\nline2"

Two printable characters in source; one real 0x0A byte at runtime.

This witness exercises that end-to-end seam against the ACTUAL
hcc binary built from CURRENT source.

WHY THIS MATTERS
----------------
The previous CORRECTION04 acceptance claimed:

  "literal LF cannot be tested via the live C build because a
   literal LF inside a C string literal breaks compilation."

That claim is FALSE; "\n" in a C string literal is the ordinary
escape sequence for byte 0x0A. This witness proves that the
end-to-end seam is available AND that the CORRECTION04 parser
genuinely handles it AND that the CORRECTION03 parser did not.

The GREEN is now backed by a real emitter->wire->parser chain,
not just by a synthetic Python byte stream.
