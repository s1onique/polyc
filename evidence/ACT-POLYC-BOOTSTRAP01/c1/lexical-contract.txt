ACT-POLYC-BOOTSTRAP01 — C1 — frozen lexical contract
======================================================

Token kind enum (frozen; do not reorder)
----------------------------------------

    TK_EOF       = 0
    TK_IDENT     = 1
    TK_INT       = 2
    TK_LPAREN    = 3
    TK_RPAREN    = 4
    TK_LBRACE    = 5
    TK_RBRACE    = 6
    TK_LBRACKET  = 7
    TK_RBRACKET  = 8
    TK_COMMA     = 9
    TK_SEMI      = 10
    TK_PLUS      = 11
    TK_MINUS     = 12
    TK_STAR      = 13
    TK_SLASH     = 14
    TK_ASSIGN    = 15

Numeric values are the canonical B0 ABI; both the PolyC
subject and the C oracle MUST emit exactly these numbers.

Punctuation → kind mapping
--------------------------

    '('  → TK_LPAREN     (3)
    ')'  → TK_RPAREN     (4)
    '{'  → TK_LBRACE     (5)
    '}'  → TK_RBRACE     (6)
    '['  → TK_LBRACKET   (7)
    ']'  → TK_RBRACKET   (8)
    ','  → TK_COMMA      (9)
    ';'  → TK_SEMI       (10)
    '+'  → TK_PLUS       (11)
    '-'  → TK_MINUS      (12)
    '*'  → TK_STAR       (13)
    '/'  → TK_SLASH      (14)
    '='  → TK_ASSIGN     (15)

Whitespace
----------

Skipped silently: `' '` (0x20), `'\t'` (0x09), `'\n'`
(0x0A), `'\r'` (0x0D). No whitespace tokens are emitted.

Identifier grammar
------------------

    ident_start  = [A-Za-z_]
    ident_rest   = [A-Za-z0-9_]*

Tokens: `TK_IDENT` with `start` = first ident_start
byte offset, `len` = total identifier length.

Integer grammar
---------------

    [0-9]+

Tokens: `TK_INT` with `start` = first digit offset,
`len` = total digit length. B0 does not parse the
numeric value; that is parser work, forbidden in B0.

Unsupported bytes
-----------------

Any byte that is not whitespace, ident_start, ident_rest,
digit, or punctuation (single-byte): lexer returns
`LEX_UNSUPPORTED_BYTE`. The byte at `src[cursor]` is the
unsupported byte; the cursor stops there (no advance is
required by the contract — see NC6). The token stream up
to that point is the partial stream.

EOF
---

When `cursor >= src_len`, or when starting from cursor ==
src_len, the lexer MUST emit exactly one `TK_EOF` token
with `start = src_len` and `len = 0`, then return
`LEX_OK` with `out_count` reflecting the EOF token.

Output capacity contract
------------------------

If, after a successful lexical decision, the next write
would write `out[out_cap]`, the lexer MUST:

    - NOT perform that write;
    - return LEX_OUTPUT_FULL;
    - leave `out_count` at the number of tokens already
      written (which is <= out_cap - 1, because at least
      the EOF slot must remain available).

If `out_cap < 1`, the lexer cannot even write the EOF
token. In that case it returns `LEX_OUTPUT_FULL` with
`out_count = 0` and no writes performed. (This is the
T12 / NC7 negative control.)

If `out_cap == 1`, the lexer writes only the EOF token
before declaring full on the next iteration.

Status codes (frozen; integer values are stable)
-----------------------------------------------

    LEX_OK                = 0
    LEX_OUTPUT_FULL       = 1
    LEX_UNSUPPORTED_BYTE  = 2
    LEX_INVALID_INPUT     = 3

`LEX_INVALID_INPUT` is reserved for genuine validity
checks on the API contract itself (NC1..NC5). It is not
emitted on T11 / NC6, which uses `LEX_UNSUPPORTED_BYTE`.

Source immutability
-------------------

`BootstrapLex` MUST NOT mutate bytes of the source
buffer. The source buffer is caller-owned and read-only
from the lexer's perspective.
