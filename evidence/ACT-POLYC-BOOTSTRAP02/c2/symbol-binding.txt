ACT-POLYC-BOOTSTRAP02 — C2 — symbol-binding
============================================

Verifies that the B1 symbol is properly bound in both the
host harness AND the stage1 binary, with the same signature
agreed by the bridge header.

Bridge declaration (src/lexer_bridge.h)
----------------------------------------

  extern long long BootstrapScanIdent(unsigned char *src,
                                      long long      src_len,
                                      long long      start,
                                      long long     *out_end);

Stage0 B1 object (build/bootstrap02-ident.o)
---------------------------------------------

  $ nm ./build/bootstrap02-ident.o | grep -i BootstrapScanIdent
  00000000000002e0 T _BootstrapScanIdent

  Symbol type: T (text section, global)
  Visibility:  default (extern)
  Mangling:    leading underscore (Mach-O arm64 ABI)
  Signature:   matches bridge declaration (verified by
               successful link into both the host harness
               and the stage1 binary below)

Stage1 host harness (build/bootstrap02-ident-host)
--------------------------------------------------

  $ nm ./build/bootstrap02-ident-host | grep -E '_BootstrapScanIdent|_main'
  0000000100000000 T _main
  0000000100003e9c T _BootstrapScanIdent

  Both symbols are present in the linked binary.
  No "undefined symbol" warnings from the linker.

Stage1 binary (build/hcc-bootstrap02)
--------------------------------------

  $ nm ./build/hcc-bootstrap02 | grep -i BootstrapScanIdent
  000000010007c318 T _BootstrapScanIdent

  $ ls -la ./build/hcc-bootstrap02
  -rwxr-xr-x  1 chistyakov  staff  742160 Sep 13 15:44 ./build/hcc-bootstrap02

  $ file ./build/hcc-bootstrap02
  ./build/hcc-bootstrap02: Mach-O 64-bit executable arm64

  Symbol present, no undefined-symbol errors at link time.

Production binary (./build/hcc)
---------------------------------

The default production build does NOT link the B1 object
(by design — it uses the legacy ctype path gated by
#ifndef HCC_BOOTSTRAP02_STAGE1). Therefore
_BootstrapScanIdent is NOT expected in ./build/hcc.

  $ nm ./build/hcc | grep -i BootstrapScanIdent
  (no output — correct)

This proves the production binary tree is unchanged from
the stage0 reference build. B0 conservation (F10) is not
violated: the production build uses the legacy code path.

Verdict
-------

  BRIDGE_DECLARATION            = PASS (src/lexer_bridge.h)
  STAGE0_OBJECT_SYMBOL          = PASS (T _BootstrapScanIdent)
  HOST_HARNESS_LINK             = PASS (B1 + host.c -> bootstrap02-ident-host)
  HOST_HARNESS_SYMBOL           = PASS (T _BootstrapScanIdent)
  STAGE1_BINARY_LINK            = PASS (B1 + hcc sources -> hcc-bootstrap02)
  STAGE1_BINARY_SYMBOL          = PASS (T _BootstrapScanIdent)
  PRODUCTION_BINARY_UNCHANGED   = PASS (no _BootstrapScanIdent in ./build/hcc)
  B1_DELEGATION_NO_FALLBACK     = PASS (no runtime branch in lexIdentifier)
