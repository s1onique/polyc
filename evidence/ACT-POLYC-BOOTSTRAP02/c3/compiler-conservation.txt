Section C — unit-test / jit-unit-test status
------------------------------------------------------------

Per evidence/ACT-POLYC-BOOTSTRAP02/c1/entry-conservation-baseline.txt,
`make unit-test` and `make jit-unit-test` are INHERITED
gates that are NOT re-runnable in this sandbox because
/usr/local/include/tos.HH is absent and the inherited
src/tests/run.HC spawn path does not pass
--install-dir to the spawned hcc.

The same condition applies at C3 entry:

  $ make unit-test
  [0;31mFailed to compile[0;0;0m: 01_pointer_simple.HC
  [0;31mFailed to compile[0;0;0m: 02_pointer_simple.HC
  ...
  rc=0 (Makefile's recipe uses && so failures inside the
        spawned test-runner do NOT propagate to make's rc)
  (this is the SAME as the C1 baseline condition)

The unit-test runner itself (built via
`./hcc --install-dir=./build/test-prefix ./run.HC`)
fails to find /usr/local/include/tos.HH when it
shells out to `../../hcc <file>` because it does NOT
pass --install-dir. This is the documented inherited
sandbox limitation. It is not a regression introduced
by C3.

  $ make jit-unit-test
  (same condition; same inherited sandbox limitation)

These gates are therefore classified
NON_BLOCKING_GOVERNANCE_RESIDUE per BOOTSTRAP01
HANDOFF.md and the C1 entry baseline. The C3
conservation verdict compares against the inherited
C1 numbers, not against the sandbox-broken
invocation.
