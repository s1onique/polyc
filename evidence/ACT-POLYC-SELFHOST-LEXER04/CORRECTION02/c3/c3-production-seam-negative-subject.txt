NEGATIVE CONTROL DESIGN
-----------------------
The C3 RED/RECON established that src/lexer.c (the production lexer)
delegates to BootstrapLinkDirective ONLY as a contract proof:
  (void)out_consumed; (void)out_is_path; (void)out_stored_len; (void)out_error;
The link_libs and shared_object_files lists are built from lexeme
content (next.start, next.len) directly, NOT from BootstrapLinkDirective
outputs.

N02 mutates BootstrapLinkDirective::LinkScanAngle to return LINK_OK
at end-of-input (where the current code correctly returns
LINK_ERR_UNTERM_ANG). The mutated .o has different SHA than pristine,
so the defect is genuinely introduced into the linked seam binary.

INTERPRETATION
--------------
The mutation introduces a real semantic defect: BootstrapLinkDirective now
returns LINK_OK for unterminated #link <...> directives. The defect is
genuinely compiled into the object file (different SHA, symbol present,
cleanly linked into the seam binary). However, the seam test output is
IDENTICAL to pristine because the production lexer.c treats BootstrapLinkDirective
outputs as contract proof only ((void) casts on all output parameters).

This is the CORRECT outcome for N02: it demonstrates that the production
seam binary's observable behavior is INDEPENDENT of BootstrapLinkDirective
semantic correctness for the L01..L10 corpus. The seam test verifies
that:
  (a) the component is loaded and callable (link-time contract),
  (b) the lexer's observable tokenization of #link directives is correct,
  (c) link_libs / shared_object_files match expectations,

but it does NOT verify the semantic correctness of BootstrapLinkDirective
itself, because the production lexer does not consume its outputs.

This finding has a positive implication for the C3 4-stage semantic
qualification: defects in BootstrapLinkDirective (component-level)
would be detected by component-level tests (component fixedpoint /
4-stage semantic pair tests), not by the production seam.
