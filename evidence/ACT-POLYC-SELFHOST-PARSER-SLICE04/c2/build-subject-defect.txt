ACT_PHASE=C2-IMPL
EVIDENCE_KIND=build-subject-defect

A FRESH-TREE DEFECT IN THE QUALIFICATION TOOL'S LINK
======================================================

THE DEFECT
----------

The first version of the SLICE04 differential's link line listed the
three existing PolyC subject objects TWICE: once in the
SLICE04_DIFF_OBJS variable and once again in the link line itself.

  SLICE04_DIFF_OBJS = ... $(SLICE03_OP_OBJ) $(PARSER_PADDING_OBJ) \
      $(SLICE02_CFT_OBJ) ...
  cc -o $@ $(SLICE04_DIFF_OBJS) $(SLICE04_ERRNO_SHIM) \
      $(PARSER_PADDING_OBJ) $(SLICE02_CFT_OBJ) $(SLICE03_OP_OBJ) ...

The link therefore failed with:

  ld: 3 duplicate symbols
    _BootstrapCalcPadding
    _BootstrapOperatorPrecedence
    _BootstrapValidPostControlFlowToken

IT WAS MASKED BY A WARM BUILD STATE
-----------------------------------

The defect did NOT fail the C2 measurement, because the objects
happened to be linked in an order in which the linker resolved the
duplicate references.  It became visible only after the libtos
archive was rebuilt and the link resolution order changed.

It is reproducible from a PRISTINE CLONE of that tree:

  COMMAND=git clone --no-hardlinks . /tmp/slice04-clean
  COMMAND=cd /tmp/slice04-clean && make build/parser-slice04-differential
  OUTPUT:
    ld: 3 duplicate symbols
    clang: error: linker command failed with exit code 1
  EXIT_CODE=2

This is precisely what F9's fresh-tree requirement exists to catch:
a warm-tree result that does not survive a cold build.

THE REPAIR
----------

The three subject objects are listed ONCE, through the transitive
object set that already carries them.  This is the minimal change that
removes the duplicate without altering the link's semantics.

  DEFECT_SCOPE=QUALIFICATION_TOOL_LINK_ONLY
  PRODUCTION_AFFECTED=NO
  EVIDENCE_AFFECTED=NO
  REPRODUCED_FROM_PRISTINE_CLONE=YES
  REPAIRED_IN_THIS_PHASE=YES
