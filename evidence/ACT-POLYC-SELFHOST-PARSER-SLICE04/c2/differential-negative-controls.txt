THE EIGHT NEGATIVE CONTROLS
===========================

ACT section 7.3 requires eight negative controls that "genuinely
execute and fail, not merely assert that an integrity check exists".

COMMAND=make parser-slice04-negative-controls

OUTPUT:

    FIXTURE_INTEGRITY_DUPLICATE_IDS=1
  SLICE04_NC_03=verifier=integrity   exit_code=nonzero result=PASS

WHAT EACH CONTROL MUTATES
-------------------------

  NC-01  a MISSING accepted token: the row F001 is DROPPED from a COPY
         of the fixture.  The independent fixture-integrity witness
         must report one fewer observed row and one missing id.
  NC-02  a DUPLICATE fixture id: the row F001 is APPENDED a second
         time to a COPY.  The integrity witness must report a
         duplicate id.
  NC-03  an UNKNOWN fixture id: a row with the id F999 is APPENDED.
         The integrity witness must report an unknown id.
  NC-04  an INDENTED unknown row: a row whose id is "  X002" (leading
         spaces) is APPENDED.  This is the bypass class that
         ACT-POLYC-SELFHOST-PARSER-SLICE-RECON03 reproduced in a closed
         tool.  The integrity witness must report an unknown row.
  NC-05  an OUT-OF-RANGE signed integer: the INT64_MIN row's token
         value is replaced with 9223372036854775808.  The differential
         must report a field parse error.
  NC-06  a MISSING semantic value: the INT64_MAX row's expected-output
         field and every field after it are dropped.  The row count is
         still correct, but the semantic value is missing.  The
         differential must report a field parse error.
  NC-07  an INCORRECTLY OVERWRITTEN output: an M09 invalid-token row's
         expected-output field is replaced with a hard-coded default
         (777), so the output appears to have been overwritten.  The
         differential must report an oracle-versus-expected mismatch.
  NC-08  a CHANGED expected enum value: the first accepted-token row's
         expected enum is changed from 3 to 99.  The differential must
         report an oracle-versus-expected mismatch.

THE VERDICT IS THE VERIFIER'S EXIT CODE
----------------------------------------

Each control RUNS the real PolyC verifier binary against the mutated
fixture and requires a NON-ZERO exit code.  The control therefore
fails if the verifier ACCEPTS a fixture it must reject.  A control that
merely asserted that a check exists would be vacuous; these controls
execute the check.

The mutated copies live under build/slice04-nc/.  The tracked
canonical fixture is NEVER modified: the mutation is applied to a COPY.

  FIXTURE_NEGATIVE_CONTROLS=PASS
  FIXTURE_NEGATIVE_CONTROLS=8/8
