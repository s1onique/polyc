THE PRODUCTION DELEGATION IS LOAD-BEARING
=========================================

THE ADAPTER
-----------
src/ast.c's astBinOpFromToken now reads:

  int astBinOpFromToken(s64 op, AstBinOp *_result) {
  #ifdef HCC_USE_SELFHOST_PARSER_AST_BINOP
      extern long long BootstrapAstBinOpFromToken(long long token_value);
      long long mapped = BootstrapAstBinOpFromToken((long long)op);
      if (mapped < 0)
          return 0;

      *_result = (AstBinOp)mapped;
      return 1;
  #else
      ... the legacy switch ...
  #endif
  }

The adapter owns ONLY argument projection, success conversion and
conditional output storage.  The token-to-operator DECISION is made by
the PolyC component.

  00000000000006bc	mov	w0, #0x1                  <- return 1
  00000000000006c0	b	0x6c8

THERE IS NO JUMP TABLE, NO SWITCH AND NO ENUM IMMEDIATE IN THIS
FUNCTION.  The body is: call, test, conditionally store, return.  The
classification decision is NOT in this object any more.

At the C0 entry the SAME function's disassembly contained the two-level
jump table and the enum immediates (`mov w8, #0x2`, `mov w8, #0x5`, ...
`mov w8, #0x11`), which is recorded in
c0/baseline-conservation.txt.  The comparison between the two
disassemblies is the direct proof that the legacy C decision left the
production path.

THE ADAPTER'S CONTROL FLOW MATCHES THE ORIGINAL C ABI
------------------------------------------------------

  the original returned 1 and wrote the enum on a recognised token
  the original returned 0 and wrote NOTHING on an unrecognised token

The adapter does exactly that:
  * `tbnz x0, #0x3f` branches to the `return 0` path when the PolyC
    component reported the -1 sentinel, so the `str w0, [x19]` store is
    REACHED ONLY ON SUCCESS;
  * the caller's output slot is therefore UNCHANGED on failure.

The unselected classifier still has its C switch and its jump table, so
it remains the legacy C authority, exactly as the ACT requires.

THERE IS NO SHADOW CALL AND NO FALLBACK
----------------------------------------

The adapter's body contains exactly ONE call, and it is the call to the
PolyC component.  There is no second call to the legacy switch, no
"compute both and compare" shadow, and no "if the component is missing
use C" fallback: the component is a LINK-TIME requirement, and the
build FAILS CLOSED when it is absent (see fail-closed-build-controls).
