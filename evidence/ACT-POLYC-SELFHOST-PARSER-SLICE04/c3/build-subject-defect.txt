THE FRESH-TREE DEFECT, AND ITS REPAIR
=====================================

The qualification tool's link line listed the three existing PolyC
subject objects TWICE, so the differential could not be linked from a
pristine clone:

  ld: 3 duplicate symbols
    _BootstrapCalcPadding
    _BootstrapOperatorPrecedence
    _BootstrapValidPostControlFlowToken

The defect was MASKED by a warm build state during the first C2
measurement.  It is reproduced from a PRISTINE CLONE of that tree, and
it is exactly what F9's fresh-tree requirement exists to catch.

THE REPAIR IS IN THE C2 PHASE
------------------------------

The repair belongs to the phase that introduced the defect: the three
subject objects are now listed ONCE, through the transitive object set
that already carries them.  ACT section 16 authorizes exactly this:
"If a mandatory issue is discovered before C4, repair it in the
authorized implementation/evidence phase if possible."

The full detail, including the pristine-clone reproduction, is in
c2/build-subject-defect.txt.

WHAT IT DOES NOT AFFECT
-----------------------

  * NO production artifact.  The production compiler is built by the
    CMake graph (src/CMakeLists.txt), which never uses this link line.
  * NO evidence claim.  Every C3 result below was re-measured from the
    CORRECTED tree, and every one reproduces its recorded value.
