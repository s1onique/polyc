THE GENERATION PROVENANCE
=========================

THE RAW RECEIPT
----------------

The raw receipt is build/slice04-gen/provenance.  It is the SINGLE
source of every field in the machine-readable manifest
(generation-manifest.tsv) and of this human-readable summary, so the
three representations cannot disagree.

  RAW_RECEIPT=build/slice04-gen/provenance

THE VERIFIED WITNESS
--------------------

COMMAND=./build/parser-slice04-provenance-verifier build/slice04-gen/provenance
OUTPUT:
  GENERATIONS_VERIFIED=4
  PROVENANCE_VERDICT=ACCEPTED

The verifier is a POLYC tool
(tools/quality/parser-slice04-provenance-verifier.HC).  The only
non-PolyC part is the `shasum` invocation, which is an
INDISPENSABLE EXTERNAL TOOLCHAIN ADAPTER: the PolyC runtime has no
SHA-256 primitive.  Every VERIFICATION DECISION is made in PolyC.

WHAT THE WITNESS BINDS
----------------------

For each generation the witness records, and the verifier re-checks
against the LIVE filesystem:

  GENERATION                 the stage label
  COMPILER_INVOCATION        the compiler the build rule actually invoked
  COMPILER_RESOLVED_PATH     that compiler's RESOLVED path
  COMPILER_BINARY_SHA256     that compiler's sha256
  SOURCE_PATH                the source that was compiled
  SOURCE_SHA256              that source's sha256
  EXACT_BUILD_COMMAND        the command that was run
  OUTPUT_OBJECT_PATH         the object that was produced
  OUTPUT_OBJECT_SHA256       that object's sha256
  PROVENANCE_NONCE           a per-generation nonce
  PROBE_EXECUTION_OUTPUT     the ACTUAL output of a probe that was
                             BUILT by that generation's own compiler,
                             LINKED against that generation's object,
                             and EXECUTED

THE EXECUTION-LINKED WITNESS IS NECESSARY
==========================================

G1, G2 and G3 produce BYTE-IDENTICAL objects
----------------------------------------------

  g1.o sha256=6d598bc7f0b00ac47642ec06b8cceba641d55a8cfe5498e0a6a995c40f2e054d
  g2.o sha256=6d598bc7f0b00ac47642ec06b8cceba641d55a8cfe5498e0a6a995c40f2e054d
  g3.o sha256=6d598bc7f0b00ac47642ec06b8cceba641d55a8cfe5498e0a6a995c40f2e054d

A finished object from one generation could therefore be SUBSTITUTED
for another WITHOUT changing the output bytes, and a check that only
compared (object SHA, compiler SHA) would NOT detect it: both fields
are copyable and relabelled.

The witness is what detects it, because the probe's OUTPUT is the
product of an ACTUAL EXECUTION of a binary that was BUILT by that
generation's OWN compiler and LINKED against that generation's OWN
object, and the recorded output must equal the recorded nonce.

  BYTE_ONLY_SUBSTITUTION_DETECTION_CLAIMED=NO
  EXECUTION_LINKED_WITNESS=YES

INVOKED COMMAND: the G0 build rule invokes `cc`, and the recorder
resolves `cc` through the PATH lookup and hashes the RESOLVED
executable.

  G0_COMPILER_SHA_MATCHES_LIVE_BINARY=YES
  G0_COMPILER_IS_THE_POLYC_COMPILER=NO
