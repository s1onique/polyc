Forward-looking discipline:

  Future ACTs in this lineage should:

  1. Use a side-branch (`git checkout -b`) for mutation testing rather
     than `git stash`. The side-branch can be deleted or merged cleanly
     without touching the agent's own state.

  2. Treat any pre-existing `git stash` entries as read-only evidence.
     Never run `git stash pop`, `git stash apply`, or `git stash drop`
     on a stash the agent did not create in the current ACT.

  3. If a stash must be dropped (e.g., during cleanup at end of ACT),
     first create a durable reference (`git stash show -p > stash.patch`
     or `git tag recovered/stash-X <commit>`) before dropping.
