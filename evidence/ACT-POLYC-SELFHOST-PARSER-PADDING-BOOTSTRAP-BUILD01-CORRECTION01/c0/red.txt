SECOND MEASURED DEFECT (PRE-EXISTING, not repaired here)
  The range check reads trailers with git's %(trailers) formatter, and
  Git 2.54.0's trailer parser drops the WHOLE trailer block when any
  key contains an underscore:
    printf 'x\n\nACT: A\nACT-Phase: CLOSE\n' | git interpret-trailers --parse
      -> ACT: A / ACT-Phase: CLOSE
    printf 'x\n\nACT: A\nACT-Phase: CLOSE\nHALT_CLASS: G\n' | git interpret-trailers --parse
      -> (empty)
  So a conforming HALT_* CLOSE commit -- which the Factory REQUIRES to
  carry HALT_CLASS and BLOCKS_NEXT -- cannot be read by the range check.
  The Factory's own precedent commit 505b007 fails identically:
    $ bash scripts/quality/factory-v2-range-check.sh \
        ACT-POLYC-AOT-PIC-EXTERNAL-REFS01-CORRECTION01 505b007
    STATUS=FAIL
    REASON=CLOSE 505b007... does not carry exactly one ACT:
           ACT-POLYC-AOT-PIC-EXTERNAL-REFS01-CORRECTION01 (count=0)

  This ACT does NOT repair that implementation (out of scope), and its
  own CLOSE therefore uses a PASS-form verdict, which is both
  mechanically parseable and truthful for a topology-only subject.
