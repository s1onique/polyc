F4 / F13 INTERPRETATION
    The premise of ACT §10 (LLVM receives IR after native fusion)
    DOES NOT REPRODUCE in the current source. The LLVM dispatch
    (main.c:561 -> irLowerProgram -> irBasicFunctionOptimisations)
    does NOT call irFunctionPrepForCodeGen, and therefore does
    NOT call irOptPinResultReg, and therefore does NOT create
    IR_CMP_BR. The IR_CMP_BR switch arm at src/llvm-backend.c:610-636
    is DEAD CODE in the current source.

    This is consistent with:
        - src/ir-types.h:140-150 ("an LLVM-style consumer does
          not need to recognise IR_CMP_BR")
        - the predecessor C1 ACT's analysis file
          evidence/llvmspike01-resume01-correction01/red-1A.analysis.txt
          which documented that RED-1A's literal claim does not
          reproduce at the --dump-ir snapshot.

    The boundary is already mechanically enforced. What is left
    is dead code that should be removed (per ACT §11: "preserve
    boundary by removing the dead arm"), or, equivalently, an
    explicit boundary assertion (per ACT §25) so the dead arm
    cannot silently re-activate if some future refactor moves
    the fusion pass into the shared pipeline.
