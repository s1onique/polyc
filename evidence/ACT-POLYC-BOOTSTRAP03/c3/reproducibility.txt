181 semantic rows match byte-for-byte.

------------------------------------------------------------
Per-artifact byte comparison (Build A vs Build B)
------------------------------------------------------------

For each of the 175 PASS-PASS stage1 sources, the
corresponding Build A and Build B .o artifacts are
compared.

```text
$ for f in build/b03-corpus-A/*.o; do
    rel=$(basename $f)
    sa=$(sha256sum "$f" | cut -d' ' -f1)
    sb=$(sha256sum "build/b03-corpus-A2/$rel" | cut -d' ' -f1)
    if [ "$sa" != "$sb" ]; then echo "DIFF: $rel"; fi
  done
(empty)
```

All 175 stage1 artifacts are byte-identical between
Build A and Build B. The same is true for stage2
artifacts in `b03-corpus-B/` vs `b03-corpus-B2/`.

------------------------------------------------------------
Why "per-artifact byte" matters
------------------------------------------------------------

The semantic equality (verdict column) is the loose
witness: both builds classify the same sources the same
way. The per-artifact byte equality is the tight
witness: the same compiler invocation produces the same
machine code, byte-for-byte, across two independent
runs.

This is the **bootstrap reproducibility** property at
the artifact level (analogous to GCC's stage2 == stage3
byte-identity check).
