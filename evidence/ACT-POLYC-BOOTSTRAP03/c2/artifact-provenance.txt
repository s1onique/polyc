------------------------------------------------------------
Provenance interpretation
------------------------------------------------------------

Both equalities hold. The **path equality** is the
strongest proof because:

1. CMake captured the path at configure time and
   embedded it in the link line.
2. The make recipe places the linker's resolved output
   path directly, so the path on disk equals the path
   embedded in the build graph.
3. No symbolic indirection, no renaming, no symlinking
   is involved in the seam.

The hash equality is expected (same backend, same
source) but is **not** the primary witness.

------------------------------------------------------------
Stage1 → stage0 B1 object (for comparison)
------------------------------------------------------------

```text
Stage0 B1 object:
  producer    = ./hcc (stage0)
  output      = ./build/bootstrap02-ident.o
  bytes       = 2704
  sha256      = a1b620c076e81d898f953889f2b9db97f0bf8f6228af3b4a10644e2e78cd854f
```

Stage0 and stage1 produce the same byte-identical B1
object (deterministic backend). The build graph still
distinguishes them: stage0 emits
`build/bootstrap02-ident.o`; stage1 emits
`build/bootstrap03-ident.stage1.o`. Stage1's link into
stage2 uses ONLY `BOOTSTRAP03_IDENT_OBJECT`, never
`BOOTSTRAP02_IDENT_OBJECT` (see src/CMakeLists.txt
stage2 block). The distinct path is the structural
guarantee that the stage2 binary is constructed from the
stage1-produced object, not the stage0-produced one.
