------------------------------------------------------------
Parameterizable seam (for stage2)
------------------------------------------------------------

The B1 build graph is parameterized by exactly two
CMake flags:

```text
HCC_ENABLE_BOOTSTRAP02_STAGE1 = ON | OFF
BOOTSTRAP02_IDENT_OBJECT       = /abs/path/to/B1.o
```

To produce stage2, B2 must add an analogous pair:

```text
HCC_ENABLE_BOOTSTRAP03_STAGE2 = ON | OFF   (new)
BOOTSTRAP03_IDENT_OBJECT       = /abs/path/to/stage1-produced/B1.o
```

with the additional invariant that the stage1-produced
object is consumed — not the stage0-produced object —
to satisfy §5's provenance witness.

------------------------------------------------------------
Stage1 → stage2 wiring answer (AC16)
------------------------------------------------------------

```text
Which build target creates stage1?
  bootstrap02-stage1 (Makefile:341)

Where is the B1 object added?
  -DBOOTSTRAP02_IDENT_OBJECT=$(CURDIR)/build/bootstrap02-ident.o
  passed to CMake, then target_link_libraries(hcc-bootstrap02 ...).

What variable/path names it?
  BOOTSTRAP02_IDENT_OBJECT (CMake cache var)
  resolved absolute path at link time.

Can that input be parameterized cleanly for stage2?
  YES — by mirroring the same pattern under new option
  HCC_ENABLE_BOOTSTRAP03_STAGE2 and new object var
  BOOTSTRAP03_IDENT_OBJECT, with the input object being
  build/bootstrap03-ident.stage1.o (built by stage1).
```

The Makefile seam must additionally ensure that:

1. The stage2 component build target depends on the
   stage1 binary (not stage0).
2. The stage1-produced object path is distinct from
   the stage0-produced object path (no silent overwrite).
3. The stage2 build target consumes the **stage1**
   object, not the stage0 object — guarded by the
   distinct path.
