    for each reused .o, including historical fallbacks)

## Object provenance binding

Each reused .o file in the broad corpus is recorded in
corpus-object-provenance.tsv with:
  - object_path (where the .o lives)
  - compiler_identity (stage0/stage1/stage2/stage3/historical)
  - compiler_binary_sha256 (sha256 of the compiler that produced it)
  - source (the .HC file)
  - mtime_irrelevant (always N/A; binding is by sha256, not mtime)
  - expected_sha256 (sha256 of the .o)

This makes the test fail-closed against stale build directories:
if a .o's hash changes without a compiler-binary change, the
provenance record must be updated, which surfaces the change.
