THE DERIVATION
-------------

v+1.  The required set is the UNION of:

  { v-1 : v in table }  UNION  { v+1 : v in table }
  UNION { INT64_MIN, INT64_MIN+1, INT64_MAX-1, INT64_MAX }
  UNION { 0, -1, 1 }

THE FALSE-SYMBOLIC-NUMERIC CHECK
------------------------------

The predecessor generator SCANNED NUMERIC FRAGMENTS OUT OF SYMBOLIC
IDENTIFIERS.  The P16 value list is:

  INT64_MIN, INT64_MIN+1, INT64_MAX-1, INT64_MAX, 0, -1, 1, and
  (each table value -1) and (each table value +1)

The digit "64" inside "INT64_MIN" / "INT64_MAX" was harvested as the
number 64.  The predecessor P16 rows F049..F059 carry the values:

  F049  value=64
  F050  value=64
  F051  value=1
  F052  value=64
  F053  value=-1
  F054  value=64
  F055  value=0
  F056  value=-1
  F057  value=1
  F058  value=-1
  F059  value=1

The value 64 appears FOUR times -- once for each symbolic identifier
that contains the digits "64".  These are FALSE SYMBOLIC NUMERICS:
they are fragments of a name, not values of the boundary domain.

P16_FALSE_SYMBOLIC_NUMERICS = 4
P16_FALSE_SYMBOLIC_NUMERIC_VALUES = {64}
P16_FALSE_SYMBOLIC_NUMERIC_ROW_IDS = {F049, F050, F052, F054}

THE CORRECTED CONTRACT MUST NOT SCAN NUMERIC FRAGMENTS.
Symbolic boundary constants are resolved EXPLICITLY (INT64_MIN,
INT64_MIN+1, INT64_MAX-1, INT64_MAX) or REJECTED.  The producer
fails rather than emitting a fixture with a false symbolic numeric.
