PASS C — boundary-amortization merge:

  The two big consolidation candidates are:
    R-F (scalar_literal_scanner = R1+R2+R3) absorbs R-K, R-L (its own subsets).
    R-H (comment_with_whitespace = R5+R6) is its own PASS C anchor.

  Boundary slots analysis for R-F vs the union of R-A + R-B + R-C
  individually migrated:

    R-A alone (countNumberLen): abi_input_slots=4, abi_output_slots=4  (src,src_len,cursor,flags; out_isfloat,out_ishex,out_err,out_end)
    R-B alone (lexNumeric):      abi_input_slots=4, abi_output_slots=5  (src,src_len,cursor,flags; out_strlen,out_i64,out_f64,out_ishex,out_kind)
    R-C alone (lexCharConst):    abi_input_slots=4, abi_output_slots=4  (src,src_len,cursor,flags; out_i64,out_strlen,out_end,out_status)
    Individual TOTAL input slots = 12, output slots = 13
    cross-boundary cursor transitions (one ABI per op) = 3

    R-F (scalar_literal_scanner) candidate ABI:
      inputs:  src, src_len, cursor, flags          (4)
      outputs: end_cursor, kind, subkind,
               i64_value, f64_value_bits,
               ishex, status, error_offset         (8)
    R-F TOTAL input slots = 4, output slots = 8
    cross-boundary cursor transitions = 1

    BOUNDARY_SLOTS(R-A)+BOUNDARY_SLOTS(R-B)+BOUNDARY_SLOTS(R-C)
      - BOUNDARY_SLOTS(R-F)
    = (12+13+3) - (4+8+1)
    = 28 - 13
    = 15
    15 >= 3 => MERGE QUALIFIES under Pass C.

    Same calculation for R5+R6 = R-H (comment_with_whitespace):
      R5 alone (lexSkipCodeComment) requires cursor-in, cursor-out
        inputs: src, src_len, cursor, flags     (4)
        outputs: end_cursor, status             (2)
      R6 alone (whitespace_dispatch) is purely dispatch logic; if
        extracted, requires cursor-in, cursor-out
        inputs: src, src_len, cursor, flags     (4)
        outputs: end_cursor, kind (whitespace/tk newline)  (2)
      Individual TOTAL = 12
      R-H candidate ABI = same shape (4 in, 2 out) = 6
      Amortization = 12 - 6 = 6 >= 3 => MERGE QUALIFIES under Pass C.

PASS C also checks: can R-F and R-H be merged into a single
scalar_or_trivia_scanner region? They produce orthogonal token
kinds and have no shared state beyond the cursor. SHARED_STATE
estimate is low (no shared scalar writes, only shared pointer
read of l->ptr). The merge would pay the cost of:
  - dispatch on byte in the PolyC component (could be done)
  - two separate output structs (subkind selector)
  - no semantic compression (numeric vs comment logic is genuinely different)
The boundary-amortization formula does NOT justify the merge (it would
merge 4 input slots + 8 output slots + 2 input slots + 2 output slots
into 4+10 = 14 slots, no real saving when the ABI must carry BOTH
kinds of output). Reject.
