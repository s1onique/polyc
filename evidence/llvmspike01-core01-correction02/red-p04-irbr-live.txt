asserted that IR_BR is dead code on the LLVM path because
IR_ICMP+IR_BR fuses into IR_CMP_BR. The reviewer pointed out
this contradicts the established pipeline recon:
  src/main.c's --emit-llvm path calls irLowerProgram
  irLowerProgram calls irBasicFunctionOptimisations
  irBasicFunctionOptimisations does NOT call irOptPinResultReg
  irOptPinResultReg is what fuses IR_ICMP+IR_BR into IR_CMP_BR
  irFunctionPrepForCodeGen (which calls irOptPinResultReg) is
  only called from native backends (aarch64.c, aarch64-jit.c,
  x86_64.c, x86_64-jit.c), never from llvm-backend.c.
