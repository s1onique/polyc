THE PINNED RUNTIME PRODUCER (D5)
  The runtime producer's identity is a frozen contract of a closed
  predecessor. Rather than weaken the check or re-pin it, the C2
  implementation makes the producer REPRODUCIBLE from a clean tree:
    1. materialize the pinned commit as a detached git worktree
    2. drive the pinned tree's OWN build graph with a header-only prefix
    3. compare the produced sha256 against the FROZEN constant
    4. fail closed on mismatch; install only on a match
  Measured: the produced producer's sha256 EQUALS the frozen constant
  exactly (3b4474213efabcda30eb2d0c0610c6e23793f876896c8e21c5e18024b1ab40f6).

  The pinned tree is used because the CURRENT tree's stage0 has a
  PRE-EXISTING compiler defect (the `@@N` asm local-label rendering
  regression) that prevents it from producing the runtime archive. That
  defect is PRE-EXISTING and separately owned; it is NOT in this ACT's
  mutation scope. See c1/c1-provenance-mechanism.txt measurements 5 and 9.

  The producer graph does NOT depend on the current tree's
  test-prefix-install, so the graph stays acyclic.

CMAKE POLICY SELECTED (D6)
  The "PARTICIPATE IN THE GENERATED-OBJECT GRAPH" policy is selected.
  A direct standalone cmake configure with delegation ON and
  -DPARSER_PADDING_PRODUCER=<stage0 hcc> participates in the
  generated-object graph: `make -C <build> hcc` produces the object
  itself. A standalone configure WITHOUT a producer and WITHOUT a
  pre-existing object fails explicitly with an actionable prerequisite
  message. It NEVER silently links the legacy implementation.
