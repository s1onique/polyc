  The DEFAULT nm on Mach-O reports a WEAK definition with the SAME
  type letter "T" as a strong definition. The type letter alone
  therefore CANNOT reject a weak symbol on Mach-O. The --no-weak
  filter removes the weak record entirely, which CAN.

--- the portable mechanism, verified IDENTICAL on both platforms ---
COMMAND=nm --format=posix --no-weak <object>

  Both Apple nm and GNU nm implement --format=posix and --no-weak
  with the SAME meaning. The type letters agree across the two:

  kind           Mach-O     ELF
  strong global  T          T
  weak           omitted    omitted
  undefined      U          U
  local text     t          t

  GNU nm does NOT accept the Mach-O-only "-m" flag (measured:
  "nm: invalid option -- m"), which is why the verifier uses the
  two-portable-flag form and not -m.
