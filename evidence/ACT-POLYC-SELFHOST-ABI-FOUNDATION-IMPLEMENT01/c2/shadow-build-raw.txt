# =====================================================================
# A REAL BUILD-GRAPH DEFECT FOUND AND FIXED DURING C2
# =====================================================================
#
# The first shadow Makefile block placed `PRODUCTION_HCC_INPUTS += $(CPA_OBJ)`
# at the END of the file, after the `$(PRODUCTION_HCC): $(PRODUCTION_HCC_INPUTS)`
# rule. GNU Make expands a rule prerequisites while the makefile is READ, so
# the appended prerequisite had NO effect on the effective build graph:
# the subject object was rebuilt, `make all` reported
#   make: Nothing to be done for "all".
# and the shadow binary silently stayed stale.
#
# This was caught by inspecting the effective graph (`make -n all` produced no
# reconfigure) and by comparing object and binary digests, exactly as the ACT
# requires. The fix moved the variable and the `+=` BEFORE the rule:
#
  604:CPA_SRC = tools/experimental/compile-print-ast-decision.HC
  605:CPA_OBJ = ./build/compile-print-ast-decision-subject.o
  ...  PRODUCTION_HCC_INPUTS = ...  (existing definition)
  ...  PRODUCTION_HCC_INPUTS += $(CPA_OBJ)
  616:$(PRODUCTION_HCC): $(PRODUCTION_HCC_INPUTS)
#
# After the fix, changing only the PolyC subject forced a reconfigure and a
# relink, and the shadow hcc digest changed accordingly
# (9a4e43bb... -> cf92dd8d... for the PolyC mutant).
