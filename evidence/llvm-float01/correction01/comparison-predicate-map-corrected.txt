Binding predicate map (authority = LLVM LangRef; aarch64 host
oracle is a corroborating witness, not the authority):

| PolyC op | IrCmpKind      | LLVM predicate | LLVM C-API constant    | proof                                           |
|----------|----------------|----------------|------------------------|-------------------------------------------------|
| ==       | IR_CMP_EQ      | ordered equal  | LLVMRealOEQ            | oeq returns false for NaN; matches cset "eq"    |
| !=       | IR_CMP_NE      | unordered not-equal | LLVMRealUNE       | une returns true for NaN; matches cset "ne"     |
| <        | IR_CMP_LT      | ordered less-than  | LLVMRealOLT        | olt returns false for NaN; matches cset "mi"    |
| <=       | IR_CMP_LE      | ordered less-or-equal | LLVMRealOLE      | ole returns false for NaN; matches cset "ls"    |
| >        | IR_CMP_GT      | ordered greater-than | LLVMRealOGT       | ogt returns false for NaN; matches cset "gt"    |
| >=       | IR_CMP_GE      | ordered greater-or-equal | LLVMRealOGE   | oge returns false for NaN; matches cset "ge"    |

Native aarch64 fcmp-on-NaN flag state: NZCV = 0011 (per ARMv8 ARM).
Mapping to aarch64 condition codes used by cset:
    mi (N=1):       NZCV=0011 -> 0 (matches olt -> false)
    pl (N=0):       NZCV=0011 -> 1
    ls (C=0|Z=1):   NZCV=0011 -> 0 (matches ole -> false)
    hi (C=1&Z=0):   NZCV=0011 -> 1
    eq (Z=1):       NZCV=0011 -> 0 (matches oeq -> false)
    ne (Z=0):       NZCV=0011 -> 1 (matches une -> true)
    gt (Z=0&N=V):   NZCV=0011 -> 0 (matches ogt -> false; Z=0 but N!=V)
    ge (N=V):       NZCV=0011 -> 0 (matches oge -> false; N=0,V=1)
    lt (N!=V):      NZCV=0011 -> 1
    le (Z=1|N!=V):  NZCV=0011 -> 1

Residue (does NOT block PASS):
  The PolyC x86_64 NATIVE backend (a separate code path from the
  LLVM backend) emits sete/setne/setb/setbe/seta/setae after
  `ucomisd` (src/x86_64.c:670-679, src/x86_64-jit.c:425-433).
  With UCOMISD setting ZF=PF=CF=1 on NaN/unordered operands, FOUR
  of six predicates produce the WRONG IEEE-754 / LangRef result:
    EQ (sete):    NaN -> 1   WRONG; expected 0
    NE (setne):   NaN -> 0   WRONG; expected 1
    LT (setb):    NaN -> 1   WRONG; expected 0
    LE (setbe):   NaN -> 1   WRONG; expected 0
  The remaining two (GT, GE) coincidentally return 0 on unordered
  and match ogt/oge; they are conservation controls. The defect
  matrix is mechanically derived in
  evidence/llvm-float01/red/recon-ll-semantics.txt (Observed
  residue section).

  The LLVM backend's choice of `olt` is TARGET-INDEPENDENT per the
  LLVM LangRef; the LLVM x86_64 code generator MUST preserve the
  `olt` semantics and cannot simply emit `ucomisd + setb` (which
  would change the result). The divergence is therefore strictly
  in the PolyC native x86_64 backend, NOT in the LLVM backend
  and NOT in any future LLVM x86_64 codegen.

  Recorded as future residue: ACT-POLYC-NATIVE-X86-FLOAT-CMP-PARITY01
  to repair the native x86_64 backend. Out of scope for this ACT.
