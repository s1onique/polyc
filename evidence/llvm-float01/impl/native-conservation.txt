ACT-POLYC-LLVM-FLOAT01 / native conservation
==============================================

ACT §10 (F10): verify required behavior changed AND unrelated
established behavior remained unchanged.

Required behavior changed:
  * Pre-FLOAT01: LLVM backend rejected any F64 source with
    LLVM_BACKEND_UNSUPPORTED_TYPE rc=1.
  * Post-FLOAT01: scalar F64 subset (param, return, constant,
    FADD, FSUB, FMUL, FCMP+BR) emits verifier-clean IR.

Unrelated established behavior (no drift):
  * I64 params / return / arithmetic unchanged.
  * I32 params / return / arithmetic unchanged.
  * F32 params / return / arithmetic unchanged (still rejected
    via the existing float-arithmetic arm for IR_FADD/IR_FSUB/
    IR_FMUL, even though IR_TYPE_F32 has long been SUPPORTED
    as a value type for return — but the FLOAT01 IMPL did not
    promote F32 float arithmetic; that promotion is a separate
    scope).
  * IR_TRUNC / IR_ZEXT / IR_SEXT / IR_FPTRUNC / IR_FPEXT /
    IR_FPTOUI / IR_FPTOSI / IR_UITOFP / IR_SITOFP /
    IR_PTRTOINT / IR_INTTOPTR still rejected with
    LLVM_BACKEND_UNSUPPORTED_CONVERSION.
  * IR_FDIV / IR_FREM still rejected with
    LLVM_BACKEND_UNSUPPORTED_FLOAT_ARITH.
  * IR_BR direct-i1 path (the FCMP consumer) unchanged.
  * IR_RET/IR_STORE work with IR_TYPE_F64 in addition to the
    previously-supported IR_TYPE_I64 / IR_TYPE_I32.
