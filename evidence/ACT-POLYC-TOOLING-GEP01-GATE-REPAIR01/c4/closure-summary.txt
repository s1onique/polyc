ROOT CAUSE / FINDING
  The four GEP01 failing rows were TWO independent defects hiding
  behind one generic harness message, not one pre-existing residue:

  (A) src/holyc-lib/io_defs.HH declared FileWrite's 4th parameter as
      `Bool append=FALSE` while io.HC and tos.HH both declare
      `I64 flags=O_CREAT|O_RDWR`. The harness includes the
      declaration-only header, so the defaulted argument was lowered
      as the boolean FALSE (0); the library issued
      open(path, 0, 420) WITHOUT O_CREAT and wrote nothing.
      -> readat.err and cap-verifier.txt were never created.

  (B) scripts/quality/llvm-cap-table-verifier.py hardcoded
      `HCC = REPO_ROOT / "hcc"`, so it queried a DIFFERENT binary
      than the harness's --hcc=<path>. On a non-LLVM build
      `hcc --print-cap-table` is unhandled and dies on SIGSEGV (139).
