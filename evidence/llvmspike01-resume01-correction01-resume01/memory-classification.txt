FIXTURE: 04_cmp_branch.HC (Max(a, b))
IR shape (post-basic-opts):
    bb1: store %l2, %p1   (local a := param 1)
    bb1: store %l4, %p3   (local b := param 3)
    bb1: alloca %t5, 8    (return-slot alloc)
    bb1: cmp_gt %t6, %p1, %p3   (compares via params, not locals)
    bb1: br   %t6, bb3, bb4
    bb3: store %t5, %l2   (ret slot := a)
    bb3: jmp  bb2
    bb4: store %t5, %l4   (ret slot := b)
    bb4: jmp  bb2
    bb2: load %t7, %t5    (ret := slot)
    bb2: ret  %t7

LLVM-emitted (verbatim):
    bb1:
      %2 = alloca i64, align 8       <-- pre-allocated for %l2
      %3 = alloca i64, align 8       <-- pre-allocated for %l4
      store i64 %0, ptr %2           <-- corresponds to store %l2, %p1
      store i64 %1, ptr %3           <-- corresponds to store %l4, %p3
      %4 = icmp sgt i64 %0, %1       <-- uses params directly!
      br i1 %4, label %bb3, label %bb4
    bb3:
      %5 = load i64, ptr %2          <-- load %l2 for ret slot
      ret i64 %5                     <-- (collapse absorbs ret slot)
    bb4:
      %6 = load i64, ptr %3          <-- load %l4 for ret slot
      ret i64 %6

CLASSIFICATION:
    %2 alloca  -> PARAM_COPY (local for param %p1)
    %3 alloca  -> PARAM_COPY (local for param %p3)
    store %0 -> %2  -> PARAM_COPY
    store %1 -> %3  -> PARAM_COPY
    load %2 -> %5    -> PARAM_COPY (consumed by ret)
    load %3 -> %6    -> PARAM_COPY (consumed by ret)

The return-slot pattern (store %t5, v; jmp; load %t5; ret) is
COLLAPSED: bb3/bb4 emit `ret <param>` directly via the existing
collapse-elimination (src/llvm-backend.c:llDetectCollapsibleReturn).
So the only memory ops that remain are PARAM_COPY.
